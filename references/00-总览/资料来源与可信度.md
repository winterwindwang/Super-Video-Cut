## 一、建库方法

- **检索日期**：2026-11-10（统一标注于各文档末尾）。
- **检索方式**：按六个能力域分工，各域做多次针对性 WebSearch / WebFetch；法规域每份 ≥3 次检索并强制优先政府/法院/标准组织一手来源。
- **总量**：约 100 次检索、50 份文档、约 55 万字（含表格与代码），来源域名 180+ 个；另含 3 个已实测脚本（2 Bash + 1 Python）。
- **命令实测**：所有 ffmpeg / ffprobe 示例均在本机 **ffmpeg 8.1.2** 验证；`06-成片审查/qc_scan.sh` 已用真实 MP4 端到端跑通（生成 probe.json / qc.log / sheet.png）。
- **写作约定**：事实性结论附可访问 URL；标准/法条写明编号与版本；无法从一手来源核实的标注「待核实」；经验参数标注为「起始建议值」。

**`08` 卷的证据特殊性**：该卷的三维评估判据与合规边界沿用 01–07 卷的 A/B 级来源；但「自进化算法」部分（η、δ、N_min、decay、容忍度、样本量、闸门门槛）**没有行业成文标准**，全部是本库自定义初始值，来源多为 2026 年行业文章与 arXiv 预印本（D 级方法论参考）。这些数字只用于让流程可运行，**不得当作经过验证的最优参数**；每积累一个真实案例应重新校准并记录。同样，`reference_probe.sh` 的 `scene > 0.25`、`silence −40 dB` 等是起始阈值，快速摇镜与闪光会误报，必须与抽帧拼图交叉验证。

## 四、复核优先级

### P0 — 影响法律结论或交付合规，引用前必须复核

1. **《著作权法》第二十四条情形数**：2020 版条文实列 **13 项**（12 项具体 + 第（十三）项兜底），部分官方解读沿用旧称「12 种」。本库按原文列 13 项。→ 核 `npc.gov.cn` 现行文本。
2. **配套法规衔接**：《著作权法实施条例》（2013 修订）与《信息网络传播权保护条例》（2006/2013）未随 2020 修法同步更新，条号与「三步检验法」表述的适用口径待明确；实施条例修订草案进度待核。
3. **平台官方协议与曲库条款**：抖音/快手/B站/视频号的版权、二创、曲库「仅本平台/非商用」限制，本库多来自法院与版权机构普法转述，**未逐条核对各平台最新协议原文**。规则变动频繁。
4. **典型案例原始裁判文书**：图解电影案、「葫芦娃」案、字体案（九层妖塔等）、AI 文生图/声音侵权案、奥特曼案——案号、当事人、判赔金额多来自媒体转述，**未取得裁判文书原文**，不得作为裁判依据直接援引。
5. **《民法典》条号一手核对**：肖像权、声音权、第 1020 条合理使用边界、第 1022 条授权解除后已发布成片的处理、第 1018–1023 条；以及《个人信息保护法》第 13 条、第 38 条起的数据出境规则。
6. **AI 相关监管与案例**：《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》关于标识、肖像/声音同意、平台义务的具体条款；EU AI Act 第 50 条、NO FAKES Act 状态；AI 案例案号。
7. **响度标准的版本与分发口径**：ATSC A/85 有 2026-07 获批新版（本库依据 A/85:2013）；EBU Tech 3344 分发阶段 −3 dBTP 为二手资料；各流媒体目标值为汇总表而非各平台原始规范。
8. **广告合规口径**：《广告法》禁用词、特殊行业资质、处罚金额区间（20 万–100 万元等表述）需按现行文本与市监部门口径复核。
9. **素材与字体许可**：Pexels / Pixabay / Unsplash 常被误标为 CC0（官方实为自有 Content License）；字体单字是否构成美术作品、思源/微软雅黑/方正商用范围；音乐库到期后已发布内容是否仍在授权内。
10. **平台技术规格**：分辨率、码率、时长上限、竖屏安全区、响度目标在不同来源间存在明显冲突（如抖音时长与码率、视频号时长），须以**平台官方创作者文档 + 上传实测**为准。
11. **风格迁移的合规边界**（`08` 卷）：思想/表达二分法在「模仿热门视频风格」场景的具体界限、AI 风格化与镜头调度复刻的定性，目前只有专家观点与普法材料，**无专门司法解释**；本库采取从严口径（只迁移参数）。商用项目必须法务复核。
12. **RSI 治理与算法参数**（`08` 卷）：η=0.05、δ=0.1、N_min=5、decay=0.9、冷却 7 天、回归/隐藏集规模、L4 偏差容忍度、场景切点阈值 0.25——**均为本库自定义初始值，无成文标准、无实证验证**。治理方法多来自 2026 年行业文章与 arXiv 预印本。每积累真实案例须重新校准并记录；冻结回归基线建立前不得批准任何规则变更。
13. **视频模型 token 与缓存口径**（`09` 卷）：静态低分辨率约 100 tok/s、高分辨率约 300 tok/s（Google《Video understanding》），Firebase 另给 263 tok/s；上下文缓存最低输入门槛 2048/4096 token、TTL 默认 1 小时、显式缓存对部分新模型不支持、Files API 文件保存期限——**各厂商与模型版本差异大且频繁变化**。`1 − 1/N` 节省式、6 MiB 采样哈希、`15–30 s 一个时间码锚点`、V1–V8 阈值均为本库自定义，无行业标准。用量一律以响应的 `usage_metadata` 为准。

### P1 — 影响选型与预算，建议定期复核

软件定价与版本（Premiere / Resolve Studio / FCP / Avid / Vegas）、硬件阈值（显存/内存/NAS/显示器色域）、TTS 引擎指标与免费额度、Netflix 字幕规范具体数值（CPS、每行字数、同步帧数，二手来源互相矛盾）、Aegisub / Subtitle Edit 版本状态、CC 协议在 NC 认定上的司法口径、集体管理组织名单与收费标准。

### P2 — 经验起调值，按项目自行校准

转场帧数、J/L-cut 偏移 8–24 帧、B-roll handles ≥12 帧、EQ/压缩/Ducking 区间、BPM 与音量层级、情绪曲线→镜头时长映射、单行字幕字数与阅读速度、笑点频率与切片发布时效、短片三幕时序。这些**没有成文标准**，用耳朵和眼睛调，别当验收指标。

## 五、复核方法

| 要核什么 | 去哪核 |
| --- | --- |
| 法律条文 | 中国人大网 `npc.gov.cn`、中国政府网 `gov.cn`、国家版权局 `ncac.gov.cn`、最高人民法院/地方法院官网 |
| 标准正文 | ITU `itu.int`、EBU `tech.ebu.ch`、SMPTE `pub.smpte.org`、ATSC `atsc.org`、W3C `w3.org` |
| 字幕/编码工具 | `ffmpeg.org` 文档 + 本机 `ffmpeg -h filter=<名称>` 实测 |
| 平台规格 | 平台官方创作者学院/帮助中心 + 上传预览实测（**不要采信第三方汇总**） |
| 素材授权 | 素材站官方 License 全文（**不是**第三方「免费商用合集」），保存带时间戳的截图与协议 |
| 案例 | 中国裁判文书网 / 法院官网 / 法院公报，取案号与生效状态 |
| 音乐权利 | 音著协 MCSC / 音集协 CAVCA 官方公告、授权合同原件 |
| 视频模型 token 与缓存 | 所用厂商官方最新文档（如 `ai.google.dev/gemini-api/docs/video-understanding`、`docs/caching`）+ 响应 `usage_metadata` 实测；**不要采信第三方汇总** |
| 素材描述与缓存工程口径 | 本库 `09-素材记忆/01`、`02`（自定义约定）；EBUCore/PBCore 仅作分层思路参考，非本库实现依据 |

复核后请在本文件追加一行：`日期 | 项目 | 结论 | 依据 URL`，并同步更新对应文档中的「待核实」标注。**不要删除原始待核实项**，保留判断轨迹。

# 字幕格式标准

> 分类：字幕系统 | 主题：字幕格式标准、时间码与封装 | 整理日期：2026-11-10 | 适用：格式选型、格式互转、软字幕封装与硬烧交付

## 一、核心原理与概念对比

字幕格式本质只回答两个问题：**什么时间**（时间轴编码）与**显示什么**（文本或图像 + 样式）。按存储形态先分两大类，再按交付形态分三种，选错类别会导致「文件打不开」「样式变字面量」「无法翻译」等完全不同类型的故障。

| 大类 | 代表格式 | 可否检索/编辑/翻译 | 典型故障 |
| --- | --- | --- | --- |
| 文本型 | SRT、WebVTT、ASS/SSA、TTML/DFXP、SCC、SBV、MicroDVD | 可 | 时间码标点、编码、样式标签不被识别 |
| 图像型 | SUB/IDX（VobSub）、PGS/.sup、EBU-STL（二进制） | 否，需 OCR | 无法改字、无法换语言、分辨率固定 |

| 交付形态 | 定义 | 能否关闭/换语言 | 是否重编码视频 | 适用场景 |
| --- | --- | --- | --- | --- |
| 外挂软字幕 sidecar | 独立 .srt/.vtt 文件与视频并列 | 能 | 否 | YouTube 上传、翻译交换、审片 |
| 内嵌软字幕 muxed | 字幕流封装进 MP4/MKV 容器 | 能 | 否（`-c copy`） | 多语言发行、站内播放器 |
| 硬烧 hardsub | 字幕渲染进画面像素 | 不能 | 是（`-vf` 必重编码） | 静音自动播放的社交短视频 |

**时间码是最大的兼容坑**：SRT 用逗号、WebVTT 用点、ASS 用点且只有两位厘秒、SCC 用帧号。同一个「1 分 2.5 秒」在各格式里写法完全不同，混用即解析失败。

## 二、各格式结构、最小示例与差异

### 2.1 SRT（SubRip）

无官方规范的事实标准，兼容性最好。结构固定为：序号 → 时间码行 → 文本行 → 空行分隔。时间码 `HH:MM:SS,mmm --> HH:MM:SS,mmm`，**毫秒前是逗号**。

```srt
1
00:00:01,500 --> 00:00:04,000
The first line of dialogue.

2
00:00:04,200 --> 00:00:07,100
And the second one.
```

仅支持极少量 HTML 风格标签（`<b>`、`<i>`、`<u>`、`<font color=...>`），且各播放器渲染不一致；不支持定位与字体。YouTube 接受纯 UTF-8 的 SRT，样式标记不被识别。

### 2.2 WebVTT（W3C 标准）

HTML5 `<track>` 与 HLS 的原生格式，UTF-8 编码，MIME 类型 `text/vtt`。文件体必须：可选 BOM → 必需首行 `WEBVTT` → 两个及以上行终止符 → 可选 REGION/STYLE/NOTE 块 → cue 块。时间码 `MM:SS.mmm` 或 `HH:MM:SS.mmm`，**毫秒前是点且必须三位**。

```vtt
WEBVTT

intro
00:01.000 --> 00:04.000 align:center position:50% size:100%
Hello.
```

要点：cue identifier 可选但在全文件内必须唯一，可被 CSS 用 `::cue(#intro)` 选中；cue settings 包括 `vertical:rl|lr`、`line:<pct|行号>[,start|center|end]`、`position:<pct>[,line-left|center|line-right]`、`size:<pct>`、`align:start|center|end|left|right`、`region:<id>`，同一列表内 setting 不得重复；cue payload 内不得出现子串 `-->`；实现不得对 Unicode 做规范化处理。STYLE 块可写 `::cue { color: lime; }`。

### 2.3 ASS / SSA（SubStation Alpha）

完整样式语言：命名样式、字体/颜色/描边/阴影、像素级定位、旋转、卡拉 OK 与动画。INI 风格分段，`Dialogue:` 行内 `{\an8}` 置顶、`{\b1}...{\b0}` 粗体等为 override tag。时间码 `H:MM:SS.cc`，**小时只有一位、毫秒位是两位厘秒**；颜色为 `&HAABBGGRR`。

```ass
[Script Info]
Title: Example
ScriptType: v4.00+
PlayResX: 1920
PlayResY: 1080

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Default,Arial,48,&H00FFFFFF,&H000000FF,&H00000000,&H80000000,0,0,0,0,100,100,0,0,1,2,1,2,10,10,40,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:01.00,0:00:04.00,Default,,0,0,0,,Hello, this is a subtitle.
Dialogue: 0,0:00:05.00,0:00:08.00,Default,,0,0,0,,This line has {\b1}bold{\b0} text.
```

SSA 是前身，用 `[V4 Styles]` 段、样式能力较少，ASS 向后兼容。`PlayResX/PlayResY` 定义样式坐标系而非视频尺寸——实测 `ffmpeg -i subs.srt subs.ass` 默认生成 `PlayResX: 384 / PlayResY: 288`，必须改成实际分辨率，否则字号与边距按错误比例缩放。

### 2.4 TTML / DFXP（W3C 标准）

XML 文档，根 `<tt>`，命名空间 `http://www.w3.org/ns/ttml`，样式用 `tts:` 前缀、参数用 `ttp:` 前缀；`head`（metadata / styling / layout）与 `body`（div / p）分离；`p` 带 `begin` / `end` / `dur`，时间值可为 clock-time `00:00:01.000` 或 offset-time `0.76s`、`3s`、`1500ms`。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<tt xml:lang="en" xmlns="http://www.w3.org/ns/ttml"
    xmlns:ttp="http://www.w3.org/ns/ttml#parameter"
    xmlns:tts="http://www.w3.org/ns/ttml#styling"
    ttp:profile="http://www.w3.org/ns/ttml/profile/dfxp-presentation">
  <head>
    <metadata/>
    <styling>
      <style xml:id="s1" tts:fontSize="22px" tts:color="white" tts:textAlign="center"/>
    </styling>
    <layout><region xml:id="r1" style="s1"/></layout>
  </head>
  <body region="r1">
    <div>
      <p begin="00:00:01.000" end="00:00:03.000">Hello TTML</p>
      <p begin="3s" dur="2s">Offset-time cue</p>
    </div>
  </body>
</tt>
```

严格文档交换时 MIME 为 `application/ttml+xml`。Netflix 交付基于 TTML1 / IMSC1.1（日语竖排），要求**字号用百分比（100%）而非像素**、定位用 `tts:textAlign` 与 `tts:displayAlign` 配合 `tts:extent` / `tts:origin`、Arial 作占位字体、且只能用其 Glyph List 内的字符——这些交付细则来自第三方整理，**标注「待核实」，以 Netflix Partner Help Center 原文为准**。

### 2.5 SCC（Scenarist Closed Captions）

美国广播 CEA-608 隐藏字幕，头部 `Scenarist_SCC V1.0`，时间码 `HH:MM:SS:FF`（**帧号而非毫秒**，按 29.97fps），数据为十六进制控制码，非人类可读文本。

```scc
Scenarist_SCC V1.0

00:00:01:15  942c 942f 94ae 94ae 9420 94f2 4865 6c6c 6f2e 942c 942f
```

各控制字（如 942c / 942f / 9420）的精确语义本次未逐字核对 CEA-608 / CTA-608 规范原文，**标注「待核实」**；仅用于识别格式与选择转换工具，勿手写控制码。

### 2.6 MOV text（tx3g）

不是独立文件，而是 MP4/MOV 容器内的文本字幕**编解码器**。ffmpeg 中对应 `-c:s mov_text`，把 SRT 转成 3GPP timed text 后封装。原生不支持 ASS 样式与定位。

### 2.7 SUB / IDX（VobSub）与同名歧义

`.idx` 是文本索引（时间点 + 语言 + 偏移），`.sub` 是位图数据。DVD 提取常见，蓝光对应 PGS `.sup`。因为是图像，**不可搜索、编辑、改样式或翻译，必须 OCR** 才能转文本。注意 `.sub` 还可能是 MicroDVD 格式（纯文本、帧号 `{100}{250}This is a line.`），两者同名但完全不同；EBU-STL `.stl` 为二进制广播格式（EBU Tech 3264）。

### 2.8 时间码与能力总表

| 格式 | 扩展名 | 1 分 2.5 秒写法 | 样式能力 | 定位 | 主要用途 |
| --- | --- | --- | --- | --- | --- |
| SRT | .srt | `00:01:02,500` | 极弱 | 无 | 通用交换、上传 |
| WebVTT | .vtt | `01:02.500` 或 `00:01:02.500` | CSS `::cue` | 有 | 网页、HLS |
| ASS/SSA | .ass/.ssa | `0:01:02.50` | 完整 | 像素级 | 特效、卡拉 OK、本地播放 |
| TTML/DFXP | .ttml/.dfxp/.xml | `00:01:02.500` 或 `62.5s` | 完整 | 有 | 流媒体/广播交付 |
| SCC | .scc | `00:01:02:15` | 有限 | 有限 | 美国广播 CC |
| SBV | .sbv | `0:01:02.500` | 无 | 无 | YouTube 上传 |
| MicroDVD | .sub | `{1499}` 帧号 | 无 | 无 | 老式播放器 |
| VobSub | .idx+.sub | 帧/时间在 .idx | 固定图像 | 固定 | DVD 备份 |

## 三、编码、BOM、轨道与语言标签（可执行规范）

| 项目 | 规范 |
| --- | --- |
| 文本编码 | 一律 UTF-8；老文件用 `-vf "subtitles=x.srt:charenc=GBK"` 转 |
| SRT / VTT 的 BOM | SRT 建议**无 BOM**，开头 BOM 会让部分解析器拒绝第一条 cue；WebVTT 规范允许可选 `U+FEFF` BOM，但仍是 UTF-8 |
| 行终止符 | WebVTT 允许 CRLF / LF / CR 三种；SRT 常规用 CRLF 或 LF |
| MP4 字幕编码 | 必须 `-c:s mov_text`；直接 `-c:s srt` 会失败或产出不可读流 |
| MKV 字幕编码 | `-c:s srt` / `-c:s ass` / `-c copy` 均可，样式保真度最高 |
| 多轨道语言标签 | `-metadata:s:s:N language=<ISO 639-2 三位码>`，如 `eng/chi/fra/spa/jpn/zho/vie`；`title=` 为播放器菜单显示名 |
| 默认轨 | `-disposition:s:0 default`，其余轨 `-disposition:s:1 0` 清除 |

**「待核实」**：MP4 只接受 ISO 639-2 三位码（用两位的 `vi` 不可靠），MKV 才支持完整 BCP 47（`zh-Hans` / `zh-Hant` 可区分简繁），此结论来自第三方整理，需按目标平台复核。**本机实测补充**：`-metadata:s:s:0 title=` 在 MP4/mov_text 下未写入（ffprobe 只显示 `language`），在 MKV 下 `title` 正常显示，因此播放器菜单名依赖 MKV 更可靠。

## 四、操作步骤与工作流（本机 ffmpeg 8.1.2 全部实测通过）

```bash
# 1. 格式互转：SRT -> ASS / WebVTT
ffmpeg -y -i subs.srt subs.ass
ffmpeg -y -i subs.srt subs.vtt

# 2. MP4 内嵌软字幕（必须 mov_text），视频音频免重编码
ffmpeg -y -i input.mp4 -i subs.srt \
  -map 0:v -map 0:a -map 1 -c:v copy -c:a copy -c:s mov_text \
  -metadata:s:s:0 language=chi -metadata:s:s:0 title="Chinese" output.mp4

# 3. MKV 双语言软字幕 + 默认轨
ffmpeg -y -i input.mp4 -i zh.srt -i en.srt \
  -map 0:v -map 0:a -map 1 -map 2 -c copy -c:s srt \
  -metadata:s:s:0 language=chi -metadata:s:s:0 title="Chinese" \
  -metadata:s:s:1 language=eng -metadata:s:s:1 title="English" \
  -disposition:s:0 default output.mkv

# 4. 查看容器内字幕轨
ffprobe -v error -select_streams s \
  -show_entries stream=index,codec_name:stream_tags=language,title -of json input.mkv

# 5. 提取内嵌字幕（第一条 / 保留 ASS 样式）
ffmpeg -y -i input.mkv -map 0:s:0 out.srt
ffmpeg -y -i input.mkv -map 0:s:0 out.ass

# 6. 硬烧：通用 subtitles 过滤器
ffmpeg -y -i input.mp4 -vf "subtitles=subs.srt" -c:v libx264 -c:a copy hard.mp4

# 7. 硬烧：ASS 专用过滤器，保留文件内全部样式
ffmpeg -y -i input.mp4 -vf "ass=subs.ass" -c:v libx264 -c:a copy hard_ass.mp4

# 8. 硬烧：覆盖样式 + 指定老字幕编码（Windows 盘符冒号需转义）
ffmpeg -y -i input.mp4 \
  -vf "subtitles='F\:/work/subs.srt':charenc=GBK:force_style='FontName=Microsoft YaHei,FontSize=48,Outline=2,Alignment=2'" \
  -c:v libx264 -c:a copy hard_styled.mp4
```

验收：每条命令后用 `ffprobe -v error -show_entries stream=index,codec_name,codec_type -of csv output.mp4` 确认字幕流存在且 codec 正确。注意 `-c copy -c:s mov_text` 的顺序——后面的 `-c:s` 覆盖前面的 `-c copy`，视频音频仍是直通。

## 五、常见错误与排查

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 字幕整段不显示 / 第一条丢失 | SRT 带 UTF-8 BOM 或序号缺失 | 另存为「UTF-8 无 BOM」，检查序号与时间码行 |
| 时间码写成 `00:00:01.500` 的 SRT 被工具判定异常 | 用了 WebVTT 的点号 | SRT 改回逗号 `00:00:01,500` |
| ASS 里写 `0:00:01,50` 解析失败 | 误用 SRT 逗号 | ASS 用 `0:00:01.50`（点 + 两位厘秒） |
| 中文显示成 `Ã©` / 问号 | 文件是 GBK / Windows-1252 | 转 UTF-8，或临时用 `charenc=` |
| MP4 加字幕报错 | 用了 `-c:s srt` | 改成 `-c:s mov_text` |
| 上传到平台后 `{\an8}` 变成字面文字 | 把 ASS 当 SRT 交付 | 先转 SRT；或走支持 ASS 的播放器 |
| 字号/边距整体偏大偏小 | ASS 的 PlayResX/Y 与视频分辨率不符 | 改成实际 `1920x1080` 等 |
| 特效字幕字体走样 | 目标机缺字体 | `ass=subs.ass:fontsdir=/path/to/fonts` |
| SUB/IDX 改不了字 | 图像型字幕 | 用 Subtitle Edit 的 OCR 转 SRT |
| 硬烧时加 `-c copy` 无字幕 | 滤镜与流拷贝互斥 | 视频必须重编码（`-c:v libx264`），音频可 `-c:a copy` |
| 多语言轨道菜单显示错语言 | 用了两位语言码 | 改用 ISO 639-2 三位码 |
| `title` 在 MP4 里看不到 | mov_text 对 title 元数据支持有限（本机实测） | 改用 MKV 交付或接受仅显示语言 |
| VTT 全文件不加载 | 缺 `WEBVTT` 首行或只换行一次 | 补首行 + 一个空行 |

## 六、速查清单

- [ ] 文本型用 UTF-8 且 SRT 无 BOM；老文件先转码
- [ ] SRT 逗号 / VTT 点 / ASS 点+两位厘秒 / SCC 帧号，未混用
- [ ] 每种格式的最小示例可独立被解析
- [ ] MP4 → `mov_text`；MKV → `srt`/`ass`/`copy`，按容器选对
- [ ] ASS 的 PlayResX/Y 等于视频分辨率，字体已随片或在 fontsdir
- [ ] 图像型字幕（SUB/IDX、PGS）已确认是否需要 OCR
- [ ] 多轨道 `language` 用 ISO 639-2 三位码，`default` 只设一条
- [ ] 硬烧必重编码视频，字幕流 copy 只用于封装
- [ ] 封装后用 ffprobe 复核 codec_name 与语言标签
- [ ] 所有「待核实」的平台细则已按官方交付指南复核

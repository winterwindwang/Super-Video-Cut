# 技术规格审查清单（Technical QC）

> 分类：成片审查 | 主题：交付前技术规格核对与自动异常检测 | 整理日期：2026-11-10 | 适用：任何成片导出后的第一道关卡；本机 ffmpeg / ffprobe 8.1.2 已实测

> ⚠️ 本文件仅覆盖**技术规格**审查，不构成法律意见；自动检测通过不代表内容合规或版权无瑕疵，须并行执行 `02-内容与合规审查.md`。

> ⚠️ 自动检测只能发现「可被算法描述」的异常（黑场、静音、冻帧、响度、解码错误）。**音画同步、字幕错别字、内容合规、版权授权、全片观感必须人工完成**，见 `02-内容与合规审查.md`。检测未报错 ≠ 成片合格。

---

## 一、审查分层

| 层级 | 手段 | 能发现 | 不能发现 |
| --- | --- | --- | --- |
| L1 自动 | ffprobe / ffmpeg 滤镜 | 规格不符、编码错误、黑场、静音、冻帧、响度超标 | 语义错误、美感问题 |
| L2 半自动 | 抽帧拼图、波形图、示波器 | 画面穿帮、构图出界、字幕遮挡、爆音 | 叙事节奏、逻辑 |
| L3 人工 | 全片通看 + 逐项对照审查表 | 音画不同步、错别字、事实错误、合规风险 | —— |
| L4 交付验证 | 目标平台实机/上传预览 | 转码后画质、音量被平台二次归一化、字幕兼容 | —— |

原则：**先 L1 全片扫，再 L3 全片看**。任何一项 L1 不通过，不必进入 L2/L3，先回炉重导。

## 二、规格核对表（对照交付单逐项打勾）

| 项 | 常见要求 | 测量命令 / 依据 |
| --- | --- | --- |
| 容器 | MP4 / MOV / MXF（按交付单） | `format_name` |
| 视频编码 | H.264 / H.265 / ProRes / DNxHR | `codec_name`, `profile` |
| 分辨率 | 1920×1080、3840×2160、1080×1920（竖屏） | `width`, `height` |
| 画幅比例 | 16:9 / 9:16 / 1:1 / 2.39:1（需与遮幅一致） | `display_aspect_ratio` + 目测 |
| 帧率 | 25 / 30 / 50 / 60 / 23.976 / 24 / 29.97 fps，全片恒定 | `r_frame_rate`, `avg_frame_rate` 两者须一致 |
| 扫描方式 | 逐行 progressive | `field_order` 应为 `progressive` / 未知 |
| 像素格式与位深 | yuv420p 8-bit（通用）；yuv422p10le（母版） | `pix_fmt` |
| 色彩标记 | 色域/传递/原色标记齐全（如 bt709/bt709/bt709） | `color_space`, `color_transfer`, `color_primaries` |
| 码率 | 按平台或母版规格（VBR 上限 / CBR） | `bit_rate`, `format.bit_rate` |
| 关键帧间隔 | 通常 1–2 秒（GOP ≈ fps × 1~2） | 抽帧观察 / `ffprobe -show_frames` |
| 音频编码 | AAC-LC / PCM / Opus | `codec_name` |
| 音频规格 | 48 kHz / 24-bit（制作）、48 kHz AAC ≥192 kbps（交付） | `sample_rate`, `bit_rate` |
| 声道 | 立体声 2.0 / 5.1，声道顺序正确 | `channels`, `channel_layout` |
| 响度 | 广播 −23 LUFS ±1 / −1 dBTP；流媒体 −14 ~ −16 LUFS / −1 ~ −2 dBTP | `ebur128=peak=true` |
| 时长 | 与交付单误差 ≤ 1 帧；含/不含彩条黑场须写明 | `format.duration` |
| 字幕 | 外挂 SRT/ASS 与画面同语言、时间轴不超片长 | 详见 `03-字幕系统/03` |
| 首尾 | 首帧非黑（除非设计如此）、结尾无突断、无残留尾帧 | 目测 + `blackdetect` |
| 文件命名 | 符合 `项目_版本_日期_规格` 约定，无中文/空格兼容问题 | 见 `01-剪辑技巧/03` |

### 一条命令取全规格

```bash
ffprobe -v error -show_entries \
  stream=index,codec_type,codec_name,profile,width,height,pix_fmt,field_order,color_space,color_transfer,color_primaries,r_frame_rate,avg_frame_rate,sample_rate,channels,channel_layout,bit_rate:format=format_name,duration,size,bit_rate \
  -of json "out.mp4"
```

## 三、L1 自动检测（命令均在本机 ffmpeg 8.1.2 实测可运行）

### 3.1 解码完整性

```bash
ffmpeg -hide_banner -nostdin -v error -xerror -i "out.mp4" -f null -
```

无任何输出即全片解码无错误。有输出说明存在损坏帧 / 时间戳异常 / 编码越界，必须定位时间码后重导。

### 3.2 黑场与冻帧

```bash
ffmpeg -hide_banner -nostdin -i "out.mp4" -an \
  -vf "blackdetect=d=0.5:pix_th=0.10:pic_th=0.98,freezedetect=n=-60dB:d=2" \
  -f null - 2>&1 | grep -E "black_start|black_end|freeze_start|freeze_end|Error"
```

- `d=0.5`：持续 ≥0.5 秒才报；刻意设计的黑场转场应缩短或列入白名单。
- `pix_th=0.10`：像素亮度阈值；`pic_th=0.98`：整帧 98% 像素达标才判黑。
- `freezedetect n=-60dB:d=2`：噪声容差 −60 dB、持续 2 秒以上判冻结。**静止画面（PPT、定格照、字卡）会误报，必须人工确认**。

### 3.3 静音段

```bash
ffmpeg -hide_banner -nostdin -i "out.mp4" -vn \
  -af "silencedetect=noise=-40dB:d=0.5" -f null - 2>&1 | grep -E "silence_start|silence_end"
```

阈值 −40 dB / 0.5 秒。注意：有持续底噪时永远测不到静音；**测不到静音不代表有人声**，还需听 300–3400 Hz 语音频段：

```bash
ffmpeg -hide_banner -nostdin -i "out.mp4" -vn \
  -af "highpass=f=300,lowpass=f=3400,volumedetect" -f null - 2>&1 | grep -E "mean_volume|max_volume"
```

### 3.4 响度与真峰值

```bash
ffmpeg -hide_banner -nostdin -i "out.mp4" -vn -af "ebur128=peak=true" -f null - 2>&1 | sed -n '/Summary:/,$p'
```

读 `Summary` 中的 `I:`（Integrated，LUFS）、`LRA:`（响度范围）、`Peak:`（True Peak）。判定口径见 `02-配音与音频/02-音频后期与混音规范.md`：

| 交付对象 | 目标 Integrated | True Peak 上限 | 依据 |
| --- | --- | --- | --- |
| 欧洲广播 | −23 LUFS ±1（文件交付建议 ±0.5） | −1 dBTP | EBU R128 / ITU-R BS.1770 |
| 美国广播 | −24 LKFS ±2 | −2 dBTP | ATSC A/85 / CALM Act |
| 流媒体通用 | −14 ~ −16 LUFS（各平台不同） | −1 ~ −2 dBTP | 平台规范，须复核 |

### 3.5 一次跑完（音视频分离，避免无音轨时报错）

```bash
ffmpeg -hide_banner -nostdin -i "out.mp4" -filter_complex \
  "[0:v]blackdetect=d=0.5:pix_th=0.10,freezedetect=n=-60dB:d=2[v];[0:a]silencedetect=noise=-40dB:d=0.5,ebur128=peak=true[a]" \
  -map "[v]" -map "[a]" -f null - 2> qc.log
```

> 该组合要求源**同时含一条视频流与一条音频流**；缺一即失败。日常批量审查建议直接用随附的 `qc_scan.sh`，它会先判断音轨是否存在再分支执行。滤镜日志走 **stderr**，`stderr 有内容不等于执行失败`。

### 3.6 抽帧拼图（L2）

```bash
ffmpeg -hide_banner -nostdin -loglevel error -i "out.mp4" \
  -vf "fps=1/10,scale=320:-1,tile=4x6" -frames:v 1 -update 1 "sheet.png"
```

每 10 秒抽 1 帧、拼成 4×6 = 24 格，覆盖约 4 分钟；长片可把 `fps` 调小（如 `1/30`）。用于快速发现穿帮、遮幅错误、字幕出界、画面骤变。

## 四、L3 人工必检项

1. **音画同步**：找 3 处明显的闭合动作（关门、拍手、敲击）与 3 处对白起音；口型偏差以帧计，>2 帧可感知。
2. **全片通看**：1.0× 速度从头到尾，不允许跳看；记录时间码 + 问题描述。
3. **字幕**：错别字、断句、时间轴重叠、单条停留过短、最后一条是否越过片长、硬烧字幕是否被 UI 遮挡。
4. **音频**：戴耳机听全片，检查爆音、齿音、底噪突变、左右声道反相、音乐压过人声。
5. **暗部与高光**：在普通显示器与手机上各看一遍，确认暗部没糊成一片、字幕在亮背景仍可读。
6. **首帧与封面**：平台默认抓取的首帧是否可用；封面文字是否落在安全区。
7. **目标平台实测**：上传预览，看平台转码后的画质、音量归一化、字幕是否被二次压制。

## 五、常见错误与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `blackdetect` 报大量黑场 | 片头片尾刻意黑场、暗场戏 | 对照时间码人工确认，列入白名单或调整 `d`/`pix_th` |
| `freezedetect` 误报 | 定格照、静态 PPT、字卡 | 人工确认；必要时把该段排除检测 |
| 测不到静音 | 有底噪 / 压缩噪声 | 提高 `noise` 阈值（如 −35 dB），并做人声频段检测 |
| `ebur128` 数值反复跳 | 只看了过程输出而非末尾 `Summary` | 一律以 `Summary` 的 `I` 为准 |
| `r_frame_rate` ≠ `avg_frame_rate` | 变帧率（VFR）素材 | 导出时强制恒定帧率 `-vsync cfr` / `-fps_mode cfr` |
| 颜色发灰或过饱和 | 色彩标记缺失或被错误打标 | 用 `-colorspace bt709 -color_primaries bt709 -color_trc bt709` 显式写入 |
| 平台上传后音量变小 | 平台二次归一化 | 按平台目标响度母版制作，不要用「做大声」硬扛 |
| 组合滤镜报 `Invalid stream specifier` | 源无音轨 | 分两条命令跑，或用 `qc_scan.sh` |
| 自动检测全绿但客户退货 | 只做了 L1 | 补 L3 全片通看与合规审查 |

## 六、交付前速查清单

- [ ] 规格表 16 项逐项对照交付单，未知项标「待确认」而非自行补数
- [ ] 解码完整性 `-xerror` 无输出
- [ ] 黑场 / 冻帧 / 静音异常区间均已播放确认
- [ ] Integrated 响度与 True Peak 达标，`Summary` 数值已记录
- [ ] 抽帧拼图已看，无穿帮、出界、遮幅错误
- [ ] 全片 1.0× 通看，音画同步抽查 6 处
- [ ] 字幕全文校对，末条未超片长
- [ ] 耳机听全片，无爆音/底噪突变/声道错误
- [ ] 首帧、封面、结尾可用
- [ ] 已通过 `02-内容与合规审查.md` 的版权与内容关卡
- [ ] 目标平台上传预览验证完成
- [ ] 审查结果填入 `03-审查表模板.md`，签署人/日期/版本号齐全

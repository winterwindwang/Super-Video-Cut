# 成片审查表模板（可直接复制使用）

> 分类：成片审查 | 主题：技术 QC + 合规 QC 的可填写表模板与批量字段定义 | 整理日期：2026-11-10 | 适用：单个项目逐项填写，或批量项目按 CSV 字段入库

> ⚠️ 表 C–G 中涉及授权与合规的判定仅为制作流程自查，**不构成法律意见**；高风险项目须由法务/专业律师复核并另附书面结论。

> 使用方式：复制「表 A–G」到项目笔记或 Excel，逐项填写。**每个「不适用」都要写明理由**，不允许空白。判定符号：`✅ 通过` / `❌ 不通过` / `⚠️ 待确认` / `— 不适用`。所有 `❌` 必须闭环到「已修复 + 复核人 + 复核日期」才可发布。

## 批量项目的 CSV 字段定义

多项目并行时，把审查结果入库。建议字段（一行一片）：

```csv
project_id,filename,version,platform,review_date,reviewer,duration_sec,width,height,fps,codec,pix_fmt,integrated_lufs,true_peak_dbtp,decode_ok,black_flag,freeze_flag,silence_flag,a_v_sync_ok,subtitle_ok,rights_cleared,compliance_ok,risk_red,risk_yellow,final_verdict,fix_version,signoff,notes
```

字段口径：`*_ok` / `*_flag` 用 `1/0/NA`；`final_verdict` 用 `pass / conditional / reject`；`NA` 必须配 `notes` 说明原因。

## 附：自动化检测脚本

同目录 `qc_scan.sh` 一次跑完规格导出、解码完整性、黑场/冻帧、静音、响度与抽帧拼图，并自动判断音轨是否存在：

```bash
bash "scripts/qc_scan.sh" "D:/output/final_v03.mp4" "D:/output/qc_logs"
```

输出：`*.probe.json`、`*.qc.log`、`*.sheet.png`。**脚本只覆盖表 B 的自动部分**，表 C–G 必须人工填写。

# RSI 自进化机制 · 总览与设计原则

> 分类：RSI自进化 | 主题：递归自改进的定义、触发协议、六层闭环、九步循环与安全护栏 | 整理日期：2026-11-10 | 适用：收到「参考某个热门视频的风格来剪」类指令时的强制工作流

> ⚠️ 本卷中的「RSI」按 **Recursive Self-Improvement（递归自改进）** 理解：系统不只改进单次剪辑结果，还改进「产生改进的那套评估—映射—审查规则」。若你指的是别的含义，请先说明，我会重新对齐。

---

## 一、要解决的问题

用户给出「参考这条爆款视频的风格剪我的素材」时，最容易出现三种失败：

| 失败模式 | 表现 | 后果 |
| --- | --- | --- |
| **印象式模仿** | 看完说「节奏快、很带感、色调高级」，然后凭感觉剪 | 风格没落到参数上，无法复现、无法审查、无法归因 |
| **表达级搬运** | 把参考片的镜头顺序、标志性音效、花字样式直接套过来 | 越过「思想/表达」边界，产生版权与不正当竞争风险 |
| **一次性判断** | 每次都从零评估，上次学到的东西不沉淀 | 第 20 次任务和第 1 次一样慢、一样不准 |

本机制用三件事分别对应：**结构化多维评估（且每项必须给出说明）** → **参数化风格指纹** → **带护栏的反馈回流**。

---

## 二、P0 触发协议（硬性，不可跳过）

当指令中出现「参考 / 模仿 / 对标 / 按…的风格 / 做成那种感觉」且指向一个具体视频时，立即进入以下状态机：

```
[收到参考视频]
   → S1 合规前置检查：素材来源合法？仅用于分析、不复用其表达？（见 05 卷 + 本卷 §六）
   → S2 客观探测：跑 scripts/reference_probe.sh，拿到可复现数值
   → S3 人工/多模态观察：看抽帧拼图、听全片、标时间码
   → S4 多维评估：填写 模板/参考视频评估表.md（7 个维度，每项四段式说明）
   → S5 汇总：产出 风格指纹 YAML + 一页评估结论
   → S6 【用户确认门】把评估结论交给用户确认或修正
        ├─ 未确认 / 有修正 → 回到 S4 修订，仍不进入剪辑
        └─ 确认 → S7
   → S7 映射为剪辑方案（04）→ 执行剪辑 → 成片审查（06 卷）
   → S8 发布后回收真实反馈 → 自进化记录（05）
```

**关键约束**：`S6 未通过前，禁止输出任何剪辑成品或最终时间线`。允许做的是评估、提问、澄清、以及提出「我理解你要的是 A 还是 B」这类确认。这条约束本身就是 RSI 不可自我修改的护栏之一。

如果只有链接没有本地文件：先说明获取方式（用户上传 / 合规下载）与平台条款风险；只有文字描述时，评估降级为 **低置信度假设模式**，所有条目置信度强制标「低」并在指纹中写明 `evidence_level: E4_assumed`，且必须在 S6 明确告知用户。

## 三、六层架构

| 层 | 名称 | 职责 | 产物 | 可自我修改？ |
| --- | --- | --- | --- | --- |
| L0 | 感知层 | 客观探测 + 带时间码的人工观察 | 切点表、响度、色彩统计、抽帧拼图 | 否（工具固定） |
| L1 | 评估层 | 7 维评估，四段式说明强制约束 | 参考视频评估表 | **仅人工确认后可改量表** |
| L2 | 表征层 | 把评估压缩成参数化风格指纹 | `sfp-v1` YAML | 可加字段，不可删必填字段 |
| L3 | 执行层 | 指纹 → 剪辑方案 → 时间线 | 剪辑方案、成片 | 可调整映射权重（受闸门约束） |
| L4 | 审查层 | 成片与指纹的偏差比对 + 06 卷审查 | 偏差表、审查表 | **否**（标准不可降） |
| L5 | 元层 | 误差归因、生成候选修订、驱动 L1/L3 演进 | 候选 diff、版本、回归结果 | **受 9 步闸门约束** |

L5 是「递归」所在：它改进的不是某条片子的剪法，而是 L1 的评估维度权重与 L3 的映射规则。普通自改进只调 L3 参数；RSI 允许在验证后调整 L1/L3 的规则本身。

## 四、九步自进化循环

采用「观察 → 诊断 → 提议 → 测试 → 比较 → 批准 → 版本化 → 部署 → 监控」，**禁止 observe→change→deploy 的直连**：

| # | 步骤 | 具体动作 | 失败即停止 |
| --- | --- | --- | --- |
| 1 | Observe | 记录预测（指纹参数、预期效果）与实际（平台数据、用户评价、审查偏差） | — |
| 2 | Diagnose | 归因到 L0 测量 / L1 评估 / L2 表征 / L3 映射 / 素材 / 外部环境 | 归因不清则记「未归因」，不进入下一步 |
| 3 | Propose | 生成**最小候选 diff**（如「短视频开场镜头时长权重 +0.1」），附来源案例 ID | diff 超过单轮漂移界即拒 |
| 4 | Test | 在冻结回归集上跑候选，与基线对比 | 任一维度低于基线即拒 |
| 5 | Compare | 与隐藏评估集、反例集比对；检查代理指标与真实目标是否同向 | 代理涨、真实跌 → 判为过拟合，拒 |
| 6 | Approve | 提交人工确认，附证据包（回归结果、diff、影响范围、回滚点） | **未签字不生效** |
| 7 | Version | 生成新版本号，保留上一版为 last-known-good | — |
| 8 | Deploy | 先影子运行，再小比例 canary，最后全量 | canary 指标异常即回滚 |
| 9 | Monitor | 持续监控漂移、资源、异常；保留 kill switch | — |

单案例只允许产生**候选**，绝不直接改规则。「一条爆款数据好」永远不构成改规则的充分理由。

## 五、七条硬护栏（RSI 不可自我修改的部分）

以下项目属于**不可变基线**，任何自进化轮次都不得改动、绕过或降级；试图修改即判定该候选失败并记入审计日志：

1. **P0 触发协议与 S6 用户确认门**。
2. **说明强制约束**：每条评估必须有观察 / 依据 / 推断 / 动作项 / 置信度，缺一即作废（见 `02`）。
3. **`05-版权法规` 卷的全部合规结论与免责声明**——不得因「上次这么做没事」而放宽。
4. **`06-成片审查` 卷的全部阻断项与技术标准**（响度、True Peak、音画同步等）。
5. **冻结回归集与隐藏评估集**：评估资产与自进化引擎权限分离，引擎不得写评估集。
6. **历史版本、反例与审计日志**：只追加，不删除、不覆盖。
7. **单轮漂移界**：权重变动 ≤0.1、规则变更 ≤2 条、每轮最多 1 个候选进入批准。

配套边界：资源上限（单次任务最大分析时长/文件数）、权限分离（提议、评估、批准、部署不同角色）、影子运行优先、可秒级停止的 kill switch。

**第 8 条（2026-11-10 由 `09-素材记忆` 卷引入，原七条编号不变）**：**素材描述卡的客观层只读**。`mdc-v1` 中 `E1`/`E2` 字段（内容哈希、时间码事实、地点凭证、客观测量、授权状态）不得由自进化引擎自动改写；纠错只能由人工确认后生成 `card_version+1` 并留 `corrections`。引擎可提议修改的只有分析提示词模板、字段权重与主题适配层规则，仍须走九步闸门与人工签字。理由：缓存会把一次错误扩散到之后所有主题，且命中记录看起来完全正常，极难发现。详见 `../09-素材记忆/04-与RSI自进化及其他卷的协同.md`。

## 六、合规前置：风格可借鉴，表达不可复制

评估参考视频前必须先立这条边界，它决定哪些维度**允许**写进指纹：

- 著作权法上「思想与表达二分法」：保护表达，不保护思想、创意、套路、方法。国家版权局转载的专家观点明确区分「借鉴创意再创作」与「照搬成形的表达」；湖北版权保护中心亦指出标准化的故事套路属于思想层面。
- **可提取**（写入指纹）：镜头时长分布、切换密度、节奏曲线、转场类型占比、响度目标、音效密度、色调倾向、结构比例、情绪曲线——这些是参数与结构。
- **不可提取**（禁止写入成片）：具体镜头内容、标志性台词、独特人物设定与造型、原片音乐与音效素材、花字具体文案与独有图形、可识别的镜头调度复刻。
- 判断标准：若把两条片子的画面并排，观众能认出「这是同一段内容被重演」，就越界了；若只觉得「节奏和气质像」，仍在风格层面。
- 侵权认定实务常用「接触 + 实质性相似」，且实质性相似比的是**表达中的取舍、选择、安排、设计**，不是主题、创意、情感。参考视频是公开发表的热门视频，「接触」几乎必然成立，因此更要严格限制在参数层。

> 本节为创作流程约束，不构成法律意见；高风险项目请法务复核，详见 `../05-版权法规/`。

## 八、元指标：怎么知道这套机制真的在变好

不能只用一个指标（会诱发过拟合）。至少同时看四组：

| 组 | 指标 | 说明 |
| --- | --- | --- |
| 评估质量 | 评估项四段式说明完整率（目标 100%）、E1 客观证据占比、S6 一次通过率 | 说明完整率是硬门槛，不是 KPI |
| 预测能力 | 指纹参数预测值 vs 成片实测值的偏差（镜头时长中位数、切换密度、响度） | 偏差收敛 = 评估在变准 |
| 结果质量 | 平台真实反馈（完播率/留存/转化）+ 用户主观确认 + 06 卷审查通过率 | 多信号，且代理指标须与真实目标同向 |
| 系统健康 | 候选拒绝率、回滚次数、规则版本数、反例保留数、漂移量 | 候选拒绝率高不是坏事，说明闸门在起作用 |

**警戒信号**：代理指标持续上升而真实反馈持平 → 疑似过拟合；内部评分异常平滑、无外部改善 → 疑似评估集被污染；反复接受又回滚近似相同的改动 → 震荡，应降低学习率并强制冷却期。

## 九、常见错误

| 错误 | 正确做法 |
| --- | --- |
| 看完参考片直接开剪 | 先完成 S2–S6，评估未确认不动时间线 |
| 用「好看/高级/有质感」当结论 | 四段式说明，落到可执行参数 |
| 把参考片的音乐/花字/镜头搬过来 | 只提取参数与结构，见 §六 |
| 一次爆款就改规则 | 只产生候选，走完九步闸门 |
| 用单个完播率驱动自进化 | 四组元指标 + 隐藏集 + 反例 |
| 让自进化引擎同时拥有评估集写权限 | 权限分离，评估集冻结 |
| 删掉「效果不好」的历史案例 | 反例必须保留，否则会系统性高估 |

## 十、速查清单

- [ ] 触发 P0，确认输入形态（文件 / 链接 / 仅描述）
- [ ] 完成合规前置检查与「可借鉴边界」告知
- [ ] 跑 `reference_probe.sh`，保存客观指标
- [ ] 7 维评估表填满，每项四段式说明 + 置信度
- [ ] 产出 `sfp-v1` 风格指纹，字段完整
- [ ] **S6 用户确认**——未确认不进入剪辑
- [ ] 映射为剪辑方案 → 剪辑 → 06 卷审查
- [ ] 记录预测 vs 实际，生成候选 diff（不直接生效）
- [ ] 回归集 / 隐藏集 / 人工批准 / 版本化 / canary / 监控
- [ ] 七条硬护栏逐条确认未被触碰

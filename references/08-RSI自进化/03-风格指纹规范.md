# 风格指纹规范（Style Fingerprint, `sfp-v1`）

> 分类：RSI自进化 | 主题：评估结论的参数化表征、YAML schema、校验与版本演进 | 整理日期：2026-11-10 | 适用：S5 阶段产出，作为 S7 映射与 L4 偏差审查的共同基准

---

## 一、定义与作用

风格指纹是**参考视频评估结论的机器可读快照**：把 `02` 里带说明的判断压缩成一组参数，使其可以被复用、被 diff、被审查、被回归测试。

它不是「好看程度评分」，也不是素材清单。四条设计原则：

1. **只装参数与结构**：只收 `02` 中经 G 过滤器标为 `transferable: parameter` 的条目，凡 `protected: expression` 一律不得出现。
2. **每个值可追溯**：必填 `source`（来源案例 ID）、`evidence`（E1/E2/E3）、`confidence`（高/中/低）、`note`（一句话说明）。
3. **置信度分级约束**：低置信度条目只能进 `hypotheses` 区，不得作为剪辑硬约束。
4. **可 diff**：纯 YAML、键名稳定、无自由文本长段落，方便版本对比与回归。

## 二、Schema 总览

```yaml
sfp_version: sfp-v1
id: SFP-20261110-001
created: 2026-11-10
source_case: CASE-20261110-001
reference:
  title: "示例：45 秒产品种草短视频"
  duration_s: 45.2
  platform: "竖屏短视频"
  genre: "04-分类型剪辑/01-短视频与Vlog"
  probe_log: "案例库/CASE-20261110-001/probe.log"
  assessment: "案例库/CASE-20261110-001/评估表.md"
evidence_summary:
  e1_ratio: 0.55          # 客观证据占全部评估项的比例
  e3_count: 4             # 解释性推断条数
  low_confidence_count: 2
  overall_confidence: 中
edit: { }        # 维度 A，见 §三
audio: { }       # 维度 B
scene: { }       # 维度 C
caption: { }     # 维度 D
narrative: { }   # 维度 E
context: { }     # 维度 F
constraints: { } # 维度 G 的汇总，必填
derived_rules: [ ]   # 由指纹推导、可直接驱动剪辑的规则
hypotheses: [ ]      # 低置信度/待验证条目，不参与硬约束
```

**必填顶层键**：`sfp_version`, `id`, `created`, `source_case`, `reference`, `evidence_summary`, `edit`, `audio`, `scene`, `constraints`。其余可为空对象但键须保留。

## 四、派生规则与假设区

`derived_rules` 是指纹到剪辑方案之间的桥，格式为可被 `04` 直接消费的规则项：

```yaml
derived_rules:
  - id: R-001
    when: "segment == opening && duration <= 3s"
    apply: "shot_len ∈ [0.8, 1.2] s, cut_count == 3"
    priority: 高
    weight: 0.8
    basis: "A1/A2 + cut_anchor_distribution"
    status: active          # active | candidate | retired
  - id: R-002
    when: "voiceover_present"
    apply: "music_duck = -6 dB; integrated_lufs target -14"
    priority: 高
    weight: 0.9
    basis: "B6/B7"
    status: active
  - id: R-003
    when: "chorus_onset"
    apply: "align cut to beat, |frame_error| <= 2"
    priority: 中
    weight: 0.5
    basis: "A9/B2"
    status: candidate       # 置信度中，先影子运行
```

`hypotheses` 存放低置信度、待验证条目，不参与硬约束，但在自进化中可作为候选来源：

```yaml
hypotheses:
  - id: H-001
    statement: "开场高密度是该账号而非该品类的特征"
    evidence: E3
    confidence: 低
    test: "再取同品类 3 条视频比对 density_curve"
```

`weight` 字段是 L5 自进化的主要操作对象；`status: active` 的规则才驱动剪辑。`candidate` 只影子运行。

## 五、校验规则（写入前必过）

| # | 规则 | 不通过的处理 |
| --- | --- | --- |
| V1 | 必填顶层键齐全 | 补齐，否则不得进入 S6 |
| V2 | 每个参数含 `value`；建议含 `evidence`/`confidence`/`source`/`note` | 缺溯源 → 退回 S4 重填 |
| V3 | 不存在任何 `protected: expression` 条目或具体素材名 | 删除并回到 G 过滤器 |
| V4 | `confidence: 低` 的条目不得出现在 `derived_rules` 的 `active` 规则中 | 降级为 `candidate` 或移入 `hypotheses` |
| V5 | 数值型参数带单位且与探测日志一致（如 `integrated_lufs` ↔ `ebur128 Summary`） | 回查 `probe.log` |
| V6 | `constraints.protected_items` 与 `forbidden_actions` 非空 | 补齐 |
| V7 | `evidence_summary.e3_count` 与推断条目数一致 | 校对 |
| V8 | 文件为合法 YAML、UTF-8、可被解析 | 修正语法 |

**建议校验命令**（若本机有 Python + PyYAML）：

```bash
python -c "import yaml,sys; d=yaml.safe_load(open(sys.argv[1],encoding='utf-8')); assert d['sfp_version']=='sfp-v1'; print('OK', len(d.get('derived_rules',[])), 'rules')" "SFP-20261110-001.yaml"
```

> 本机（2026-11-10）已核实**未安装 PyYAML**：上述命令需先 `pip install pyyaml`，或改用任意 YAML 解析器。未安装解析器时至少做基础检查——UTF-8 编码、无 Tab 缩进、V1 必填顶层键存在、V6 的 `constraints.protected_items` 与 `forbidden_actions` 非空。

## 六、版本演进

- `sfp-v1` 为**每案例一个实例**的版本，不等于规则库版本。规则库版本另用 `rules-vN` 记录于 `06-案例库与版本治理.md`。
- 允许演进：新增字段（向后兼容）、修订 `weight` 与 `status`、把 `hypotheses` 升级为 `derived_rules`。
- 禁止演进：删除必填键、改变已有键含义、静默覆盖旧指纹。
- 每次修订生成新 `id` 并保留旧文件；diff 必须附在自进化记录中。
- 指纹与评估表、探测日志通过 `source_case` 关联，三者不得分离归档。

## 七、速查清单

- [ ] 只含 `transferable` 参数，无具体表达
- [ ] 每个值可追溯到评估表条目与探测日志
- [ ] 低置信度条目已进入 `hypotheses`，未当硬约束
- [ ] `derived_rules` 的 active/candidate 状态正确
- [ ] `constraints` 非空且列明禁止动作
- [ ] 通过 V1–V8 校验
- [ ] 与 `source_case` 三件套（评估表 / 日志 / 指纹）一同归档

# 反馈回流与自进化算法（有界 RSI）

> 分类：RSI自进化 | 主题：误差归因、候选修订、权重更新、九步闸门与防漂移 | 整理日期：2026-11-10 | 适用：每次任务完成并回收真实反馈后；L5 元层

> ⚠️ 本文为创作流程参考，**不构成法律意见**；涉及授权与合规的决策请查阅 05-版权法规卷并由法务复核。

> ⚠️ 本卷的核心约束：**单案例只能产生候选，绝不直接改规则**。所有自进化都必须穿过闸门、拿到人工签字、生成新版本。任何「observe → change → deploy」的直连都视为违规。

---

## 一、数据流

```
评估表 + 指纹（预测）
   → 剪辑方案（含降级与冲突裁决）
   → 成片 + 06 卷审查 + L4 偏差表
   → 发布后真实反馈（平台数据 / 用户评价 / 复购与复用）
   → 【自进化记录】预测 vs 实际
   → 误差归因
   → 候选 diff（不生效）
   → 九步闸门
   → 规则库新版本 或 驳回（反例归档）
```

**没有真实反馈时**：不得启动自进化。可以把任务记为 `pending_feedback`，但不得用「我觉得效果不错」代替观测。审查通过、L4 偏差达标属于**内部信号**，只用于诊断，不用于证明「变好了」。

## 二、自进化记录字段

每次任务一条，写入 `案例库/<CASE-ID>/自进化记录.md`（模板见 `模板/自进化记录模板.md`）：

| 字段 | 说明 |
| --- | --- |
| `case_id` / `sfp_id` / `rules_version` | 关联三件套与所用规则版本 |
| `predictions` | 每条 active 规则的预期效果（可量化的优先） |
| `observed` | 平台数据 + 用户确认 + L4 实测偏差 + 06 卷审查结论 |
| `signal_sources` | 数据来自哪里、时间窗、样本量、是否受投放/时段/封面等外部因素干扰 |
| `attribution` | 归因结论（见 §三），未归因也要写明 |
| `candidate_diffs` | 最小修订提议，含影响范围与回滚点 |
| `gate_results` | 九步每步结果、证据、拒绝原因 |
| `decision` | 批准 / 驳回 / 待观察；签字人与日期 |
| `counterexample` | 若驳回，永久保留为反例 |

**多信号原则**：至少同时记录 ① 平台量化数据、② 用户主观确认、③ L4 偏差、④ 审查通过率。只靠完播率一项驱动改规则，是最典型的过拟合入口。

## 三、误差归因分类（诊断先于提议）

| 类别 | 典型症状 | 该动哪一层 | 是否允许自进化 |
| --- | --- | --- | --- |
| **A 测量误差** | 探测日志数值与人工复核不符、切点误报 | L0 工具参数（阈值） | 可，但阈值改动也要走闸门 |
| **B 评估误差** | 评估项说明完整但结论错；低置信度被当硬约束 | L1 维度权重 / 置信度门槛 | 可 |
| **C 表征误差** | 指纹丢了关键关系（只留均值没留曲线） | L2 字段结构 | 需人工批准（结构变更） |
| **D 映射误差** | 缩放/适配不合理、冲突裁决错误 | L3 映射规则与权重 | 可，主要操作对象 |
| **E 执行误差** | 方案正确但剪辑没照做、导出参数错 | **不改规则**，改执行 | 否 |
| **F 外部环境** | 投放时段、封面、话题热度、平台算法变动、素材质量 | **不改规则** | 否 |

归因是**必填项**。归因不清时写「未归因」并停在步骤 2，不生成候选。经验上大量「效果不好」其实属于 E/F，如果让自进化引擎去改规则，只会把规则越改越歪。

## 四、候选修订生成规则

一个候选必须满足：

1. **最小性**：一次只改一处（一个权重、一个阈值、或一条规则的 `status`）。
2. **可归因**：绑定至少 `N_min = 5` 个**同向**归因样本，且这些样本不能全部来自同一条视频/同一账号。
3. **可量化**：写明改前值、改后值、预期影响、回滚点。
4. **不触碰硬护栏**（见 `01` §五）。
5. **单轮漂移界**：权重变动 `|Δw| ≤ 0.1`；规则变更 ≤2 条；每轮最多 1 个候选进入批准。
6. **冷却期**：同一规则 7 天内不重复修订，防震荡。

### 权重更新（只生成候选值，不直接写入）

```
error_r   = clip( normalize(observed - predicted), -1, 1 )
support   = min(1, n_same_direction / N_min)            # N_min = 5
recency   = decay ^ (Δt_days / τ)                        # decay=0.9, τ=30 天
Δw        = η · error_r · conf_r · support · recency     # η = 0.05
w_cand    = clip( w_old + Δw, w_min, w_max )             # [0.0, 1.0]
           且强制 |w_cand - w_old| ≤ δ                    # δ = 0.1
```

- `conf_r`：规则置信度系数（高 1.0 / 中 0.6 / 低 0.2）。
- `decay`：让旧证据自然失重，避免三年前的平台环境仍主导今天的参数。
- **这套公式只产出 `w_cand`**，写进候选 diff；只有走完 §五 的闸门才允许成为新的 `w`。
- 结构级变更（新增/删除维度、改指纹 schema）不适用本公式，一律走人工评审。

**反例必须保留**：任何被驳回的候选连同原因永久归档。若同一方向连续 3 次被驳回，该方向进入冻结名单，除非出现新的强证据否则不再提议。

## 五、九步闸门的判定标准

| # | 步骤 | 通过条件 | 拒绝后 |
| --- | --- | --- | --- |
| 1 Observe | 四组信号齐备，signal_sources 可追溯 | 记 `pending_feedback` | — |
| 2 Diagnose | 归因到 A–D 之一且写明理由 | 记「未归因」并停止 | — |
| 3 Propose | 满足 §四 全部 6 条 | 归档为反例 | — |
| 4 Test | **冻结回归集**（固定 10 个参考案例 + 人工标注基线）上，四组元指标**无一低于基线 2%** | 归档，附回归结果 | — |
| 5 Compare | **隐藏集**（3 个，从不参与候选生成）表现不退化；代理指标与真实目标同向 | 判过拟合，归档 | — |
| 6 Approve | 人工签字；证据包含回归结果、diff、影响范围、回滚点 | 不生效 | — |
| 7 Version | 生成 `rules-vN+1`，上一版标记 `last-known-good` 且不可删 | — | — |
| 8 Deploy | 影子运行 ≥3 个案例 → canary（≤20% 案例）→ 全量 | 任一阶段异常立即回滚 | — |
| 9 Monitor | 持续监控漂移量、候选拒绝率、回滚次数、kill switch 可用 | 异常即触发 kill switch | — |

**通过门槛**：主指标至少一项提升 ≥3%，且无任何指标下降 ≥2%。宁可少改，不可多改。

## 六、防漂移机制（缺一不可）

| 机制 | 具体做法 |
| --- | --- |
| **不可变基线** | 冻结回归集与隐藏评估集独立存放，自进化引擎**无写权限**；人工维护 |
| **权限分离** | 提议、评估、批准、部署四个角色分离；引擎不得批准自己的提议 |
| **多信号验证** | 平台数据 + 用户确认 + L4 偏差 + 审查通过率；隐藏集 + 对抗样本 |
| **反例保留** | 驳回候选、失败案例、负向反馈永久保留，防止系统性高估 |
| **漂移界与冷却** | δ=0.1、≤2 条/轮、7 天冷却；超限即拒 |
| **影子与灰度** | 先影子（只记录不生效），再 canary，最后全量 |
| **可回滚** | 每版保留 `last-known-good`；回滚是命令而非祈祷 |
| **kill switch** | 在 `案例库/_config.yaml` 设 `evolution_enabled: false` 即全局停用，立即回到 `last-known-good` |
| **审计日志** | 只追加：谁、何时、提议什么、依据、闸门结果、签字、回滚点 |

**警戒信号与处置**：

| 信号 | 疑似问题 | 处置 |
| --- | --- | --- |
| 代理指标持续上升、真实反馈持平 | 过拟合 / 评估集污染 | 停轮，检查评估集权限与隐藏集 |
| 内部评分异常平滑、无外部改善 | 评估器被污染 | 用独立维护的评估套件复核 |
| 反复接受又回滚近似相同改动 | 震荡 | 降 η、延长冷却期、提高支持样本门槛 |
| 候选拒绝率长期为 0 | 闸门形同虚设 | 人工审计闸门判定记录 |
| 触及硬护栏的提议 | 目标漂移 | 该候选直接失败并记入审计日志 |

## 七、伪代码

```text
function evolve(case):
    rec = load_record(case)
    if not rec.signal_sources.complete:        return PENDING_FEEDBACK
    cause = attribute(rec)
    if cause in {E_执行, F_外部, 未归因}:      return ARCHIVE_NO_CHANGE

    cand = propose_min_diff(cause, rec)
    if not passes_hard_rails(cand) or drift(cand) > DELTA:
        archive_counterexample(cand, "rail_or_drift"); return REJECTED
    if support(cand) < N_MIN or in_cooldown(cand):
        archive_counterexample(cand, "support_or_cooldown"); return REJECTED

    if regression(cand, FROZEN_SET) degrades_any(threshold=0.02):
        archive_counterexample(cand, "regression"); return REJECTED
    if hidden_eval(cand) degrades or proxy_diverges_from_true:
        archive_counterexample(cand, "hidden_or_proxy"); return REJECTED

    if not human_signoff(cand, evidence_pack):
        return AWAITING_APPROVAL

    version = commit_rules(cand, keep_last_known_good=True)
    if not shadow_run(version, cases=3):        rollback(version); return REJECTED
    if not canary(version, share=0.2):          rollback(version); return REJECTED
    promote(version)
    monitor(version)
    return PROMOTED
```

注意 `human_signoff` 是**不可绕过的同步阻塞点**；影子与灰度失败都直接回滚，不做「再观察观察」。

| 对象 | 是否允许 | 条件 |
| --- | --- | --- |

## 九、常见错误

| 错误 | 后果 | 纠正 |
| --- | --- | --- |
| 一条爆款就改规则 | 把噪声当规律 | N_min=5 同向样本 |
| 效果不好就改规则 | 把执行/外部因素写进规则 | 先归因，E/F 类不改规则 |
| 用内部评分证明「变好了」 | 代理过优化 | 隐藏集 + 真实反馈多信号 |
| 引擎能写评估集 | 评估器污染 | 权限分离、冻结 |
| 删掉失败案例 | 系统性高估 | 反例永久保留 |
| 多改动一次上线 | 无法归因、无法回滚 | 一次一处、最小 diff |
| 影子/canary 异常仍继续观察 | 影响面扩大 | 立即回滚 |
| 长期不审计闸门 | 闸门失效 | 定期人工审计拒绝率与签字记录 |

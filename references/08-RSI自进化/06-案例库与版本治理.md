# 案例库与版本治理

> 分类：RSI自进化 | 主题：案例归档结构、命名、规则版本、审计与回滚 | 整理日期：2026-11-10 | 适用：每次评估/剪辑/自进化任务的留痕与可恢复性

> ⚠️ 本文为创作流程参考，**不构成法律意见**；涉及授权与合规的决策请查阅 05-版权法规卷并由法务复核。

---

## 一、为什么治理是 RSI 的一部分

自进化系统如果没有版本治理，就不是「在改进」，而是「在漂移」。行业共识很直接：每次自修改都必须留下不可变审计记录、可识别的已知良好版本，以及经过测试的回滚路径；否则审批、事后归因与事故响应全部失去依据。

本卷把治理落到**目录、文件名、版本号、日志格式**四件可检查的事上。

## 二、目录结构

```
08-RSI自进化/
├── 案例库/
│   ├── README.md                   案例索引表（本卷子文件）
│   ├── _config.yaml                全局开关与规则库版本指针
│   ├── _rules/                     规则库版本
│   │   ├── rules-v1.yaml           （初始基线，last-known-good）
│   │   ├── rules-v2.yaml
│   │   └── CHANGELOG.md
│   ├── _frozen/                    冻结回归集 + 隐藏评估集（引擎无写权限）
│   │   ├── regression/            ≥10 个案例，人工标注基线
│   │   ├── hidden/                3 个案例，从不参与候选生成
│   │   └── BASELINE.md            四组元指标基线数值
│   ├── _audit/                     只追加审计日志
│   │   └── audit-2026.md
│   ├── _counterexamples/           被驳回候选与失败案例（永久保留）
│   └── CASE-YYYYMMDD-NNN/          单个案例三件套 + 产物
│       ├── 评估表.md
│       ├── 风格指纹.yaml
│       ├── probe.log / probe.json / sheet.png
│       ├── 剪辑方案.md
│       ├── 成片审查表.md
│       └── 自进化记录.md
```

**三件套不得分离**：`评估表` + `风格指纹` + `probe 日志` 通过 `source_case` 相互引用，缺任一件该案例不得进入回归集。

## 三、命名规范

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 案例 ID | `CASE-YYYYMMDD-NNN` | `CASE-20261110-001` |
| 指纹 ID | `SFP-YYYYMMDD-NNN` | `SFP-20261110-001` |
| 规则版本 | `rules-vN` | `rules-v3` |
| 候选 diff | `CAND-<CASE-ID>-NN` | `CAND-CASE-20261110-001-01` |
| 反例 | `CX-<CASE-ID>-NN` | `CX-CASE-20261110-001-01` |
| 审计日志 | `audit-YYYY.md` | `audit-2026.md` |

文件名一律不含空格；中文目录名保持本知识库既有约定；日期用 `YYYYMMDD`，便于排序。

## 四、规则库版本治理

`_rules/rules-vN.yaml` 存放 `derived_rules` 的正式版本与权重，字段与 `03` 的 `derived_rules` 一致，另加：

```yaml
version: rules-v3
created: 2026-11-10
parent: rules-v2
status: last-known-good        # candidate | active | last-known-good | retired
source_cases: [CASE-20261110-001, CASE-20261110-004, ...]
candidate: CAND-CASE-20261110-004-01
gate_results:
  regression: pass
  hidden_eval: pass
  human_signoff: "张三 / 2026-11-10"
rollback_to: rules-v2
rules: [ ]
```

**规则**：
- 每次批准生成新版本号，**绝不原地覆盖**。
- 任一时刻有且仅有一个 `last-known-good`，且该版本不可删除、不可修改。
- `status` 生命周期：`candidate → active → last-known-good → retired`；被回滚的版本标 `retired` 并写明原因。
- `CHANGELOG.md` 每条记录：`版本 / 日期 / 候选 ID / 改动内容 / 依据案例 / 闸门结果 / 签字人 / 回滚点`。

`_config.yaml`：

```yaml
evolution_enabled: true          # kill switch：false 立即全局停用并回到 last-known-good
active_rules_version: rules-v3
last_known_good: rules-v3
learning_rate_eta: 0.05
max_drift_delta: 0.1
min_support_n: 5
cooldown_days: 7
frozen_set_write_allowed: false  # 引擎永无写权限
```

## 五、审计日志格式（只追加）

`_audit/audit-YYYY.md` 每行一条，禁止修改或删除历史行：

```markdown
| 2026-11-10 15:02 | CAND-CASE-20261110-004-01 | 提议 R-003 weight 0.5→0.58 | 依据 CASE-001/002/004/007/009 | 回归 pass / 隐藏 pass | 批准 张三 | 部署 rules-v4 影子 | 回滚点 rules-v3 |
| 2026-11-10 15:40 | CAND-CASE-20261110-004-02 | 提议放宽镜头时长容忍度 | 依据 CASE-004 单案例 | 回归 fail (评估质量 −3.1%) | 驳回 → CX-...-02 | — | — |
```

必填六项：时间 / 候选 ID / 改动 / 依据 / 闸门结果 / 决定与签字。缺项的记录视为无效，相应版本不得部署。

## 六、回滚流程

1. 触发条件：canary 异常、真实反馈显著退化、审计发现护栏被触碰、kill switch 被手动关闭。
2. 立即把 `_config.yaml` 的 `active_rules_version` 指回 `last-known-good`，`evolution_enabled: false`。
3. 在审计日志追加一行，记录触发原因、时间、影响范围。
4. 把被回滚版本标 `retired`，写清原因；**保留其文件与候选 diff**。
5. 生成 `CX-*` 反例，附回归与线上数据对比。
6. 冷却期内不接受同方向候选；复盘完成且人工签字后才可重新启用自进化。

回滚是**一条配置改动**，不依赖重新计算或重新训练。

## 七、冻结集与隐藏集

| 集合 | 规模 | 用途 | 维护方 | 引擎权限 |
| --- | --- | --- | --- | --- |
| 冻结回归集 | ≥10 个案例 | 检查候选是否让任一维度退化 | 人工 | **只读** |
| 隐藏评估集 | 3 个案例 | 检测代理过优化与评估器污染 | 人工 | **不可见、不可写** |
| 反例集 | 全部驳回候选 | 防止重复提议与系统性高估 | 引擎追加、人工复核 | 只追加 |

`BASELINE.md` 记录四组元指标基线（评估质量 / 预测能力 / 结果质量 / 系统健康），每次回归都以此为对照；基线本身变更须人工签字并留旧值。

## 八、归档与保存

- 每个案例至少保存：评估表、指纹、探测日志与拼图、剪辑方案、成片审查表、自进化记录。
- 参考视频**本体**是否留存取决于授权与存储成本；若不留，须在评估表中写明获取方式与关键帧截图位置，保证结论可复核。
- 涉及授权凭证、出镜同意、审查签字的文件与案例一并归档，保存期限不短于作品发布周期 + 争议追溯期（见 `../06-成片审查/03-审查表模板.md`）。
- 案例索引表（`案例库/README.md`）每新增一个案例追加一行，不做删除。

## 九、与全库索引同步

新增案例或规则版本时，只需更新 `案例库/README.md` 索引；**不需要**改动 `../SKILL.md` 与 `manifest.csv`（它们记录能力与文档，不记录案例数据）。但若新增、删除、改名本卷的**文档或脚本**，必须同步：

- `../SKILL.md` 的路由表（仅在新增独立主题或新脚本时）
- `00-总览/manifest.csv`（相对 references 根）
- `00-总览/知识地图.md` 的能力域表
- `00-总览/资料来源与可信度.md`（若引入新来源或新待核实项）

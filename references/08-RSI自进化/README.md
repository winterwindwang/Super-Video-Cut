# 08 · RSI 自进化卷

> 分类：RSI自进化 | 主题：参考热门视频风格剪辑时的评估—映射—审查—自进化闭环 | 整理日期：2026-11-10 | 适用：触发词「参考 / 模仿 / 对标 / 按…的风格」

**一句话**：当你说「参考这条爆款视频的风格剪我的素材」，我**先逐维度评估并给出说明，你确认后才开始剪**；每次任务的预测与真实结果会回流，让评估与映射规则在护栏内逐步变准。

---

## P0 触发协议（贴在墙上）

```
收到参考视频
  S1 合规前置：只分析、不复用其表达
  S2 跑 scripts/reference_probe.sh → 客观指标
  S3 全片通看 2 遍（一遍画面、一遍只听声音）+ 关键段逐帧
  S4 填 模板/参考视频评估表.md
       A 剪辑手法 / B 音效 / C 场景 逐子项
       每项必须：观察 → 依据 → 推断 → 动作项 → 置信度
  S5 产出 风格指纹 YAML + 一页结论
       三条最关键特征 + 三条不可迁移项 + 置信度总评
  S6 ★ 交给你确认 ★  ← 未确认，禁止输出成片
  S7 映射剪辑方案 → 剪辑 → 06 卷审查
  S8 回收真实反馈 → 候选修订（不直接生效）→ 九步闸门
```

**四条不可让步**：说明强制约束（没有说明的判断丢弃）、S6 用户确认门、思想/表达边界（只迁移参数不迁移表达）、单案例只产生候选。

## 三维评估速览

| 维度 | 10 个子项 | 核心问题 |
| --- | --- | --- |
| **A 剪辑手法** | 镜头时长分布、切换密度曲线、切点依据、转场类型与帧数、景别序列、镜头内动能、J/L-cut、B-roll 占比、卡点帧差、帧率与升格 | 节奏骨架是什么？切点为什么在这里？ |
| **B 音效与声音设计** | BPM 与音乐结构、音乐进出点、人声类型与占比、音效密度与类型、音效-切点耦合、电平与 ducking、响度与真峰值、声音桥、静音留白、频段与播放环境 | 是音乐驱动剪辑，还是剪辑驱动音乐？ |
| **C 场景与画面** | 场景清单、切换频率、构图、机位与景别习惯、光线与色温、色彩统计、运动与稳定、画幅与安全区、画面内元素、场景叙事功能 | 哪些是结构（可迁移），哪些是内容（不可迁移）？ |

## 一条评估长什么样（示范）

> **A3 切点依据**
> ① 观察：00:07.12 硬切，中景→产品特写；切点在抬手动作启动后第 3 帧；31 个切点中 22 个落在动作/台词断点。
> ② 依据：探测脚本切点表（E1）+ 00:07.08/07.12 逐帧比对（E2）。
> ③ 推断：动作接动作的隐形剪辑，用动量跨接缝，把注意力从人物转到产品。
> ④ 动作项：本项目产品揭示镜头切点置于动作峰值前 1–2 帧；其余对齐台词/呼吸断点。
> ⑤ 置信度：高（E1 可复现，模式重复 22/31 次）。
> G 标签：`transferable: parameter`

被丢弃的反例：「这个视频剪辑很流畅，很有电影感」——无观察、无依据、无动作项、无置信度。

## 配套：自有素材先查缓存

若任务同时要「用我的素材」，**评估参考片之前先按 `../09-素材记忆/README.md` 的 P0 协议跑 `lookup`**：命中就直接读素材描述卡（讲了什么 / 在哪拍 / 什么风格），不再请求视频模型；未命中才做一次全量分析并登记。这样多个主题复用同一素材时，只花一次模型调用。

## 首次使用

1. 把参考视频放到本地（或告诉我获取方式）。
2. 我会先跑客观探测 + 完成评估表，把**一页结论**交给你确认。
3. 你确认或修正后，我才开始出剪辑方案。
4. 交付后如果能拿到发布数据，我会记一条自进化记录（只产生候选，不擅自改规则）。

> ⚠️ 本卷不构成法律意见。风格与套路属思想层面可借鉴，具体镜头、台词、音乐、花字等表达不可复制；商用项目请法务复核，详见 `../05-版权法规/`。

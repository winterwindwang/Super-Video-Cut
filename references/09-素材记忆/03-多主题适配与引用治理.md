# 多主题适配与引用治理

> 分类：素材记忆 | 主题：同一素材被多个主题同时采纳时的分层、引用、冲突与撤销 | 整理日期：2026-11-10 | 适用：素材库复用、系列化内容、A/B 版本套剪、跨项目共享素材

> ⚠️ 本卷为工程与创作流程参考，**不构成法律意见**；同一素材在不同用途/地域/期限下的授权范围可能不同，须回查 `../05-版权法规/` 与授权凭证。

---

## 一、问题：为什么「主题适配」必须另起一层

用户的核心场景是「**一个素材可以被很多不同的主题同时采纳**」。四个主题用同一段海边日落：

| 主题 | 取用片段 | 叙事角色 | 剪法 |
| --- | --- | --- | --- |
| 秋日怀旧 | 00:03–00:08 | 情绪开场空镜 | 慢放 80%、暖调微增、留白 1 s |
| 气候科普 | 00:12–00:19 | 云层示意（信息画面） | 原速、加标注箭头、配解说 |
| 旅游推广 | 00:00–00:05 | 目的地建立镜头 | 硬切接入、叠地名条 |
| 品牌片尾 | 00:20–00:24 | Logo 前的收束 | 压暗 15%、音乐淡出 |

四条的**客观事实完全相同**：黄昏、海边、有礁石、无人声、镜头缓慢右移、YAVG 逐渐下降。若把「适合做秋日开场」写进素材卡，其余三个主题读到的是噪声；若为每个主题重看一遍视频，缓存就白做了。所以：

- **L1 MDC**：一份素材一张卡，只存主题中立的事实与推断，所有主题共享。
- **L2 主题适配**：`(material_id, theme_id)` 一条记录，存「这个主题下怎么用」，可无限追加、可撤销、互不影响。

这对应 PBCore/EBUCore 一类视听元数据标准里「**智力资产（work）与实例化（instantiation）分离**」的思路：一段素材是资产，每个主题里的用法是它的一次实例化。

## 二、L2 适配记录字段

存放位置：`缓存库/themes/<MID>.csv`（机器读）+ `模板/主题适配记录模板.md`（单条详版，人读）。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `theme_id` | str | ✓ | `T-YYYY-<短名>`，如 `T-2026-秋日怀旧` |
| `theme_title` | str | ✓ | 主题或成片标题 |
| `adapted_at` | ISO datetime | ✓ | 记录时间 |
| `clip_ranges` | list | ✓ | `MM:SS-MM:SS` 区间，可多段；须落在 `identity.duration_s` 内 |
| `narrative_role` | enum | ✓ | `开场钩子 / 铺垫 / 论证画面 / 情绪高点 / 转场 / 收束 / B-roll / 证据材料` |
| `rationale` | 五段式 | ✓ | 观察 / 依据 / 推断 / 动作项 / 置信度；**依据必须引用 MDC 的字段或时间码** |
| `edit_directives` | list | — | 变速、裁切、调色倾向、字幕叠法、音频处理的具体参数 |
| `audio_handling` | str | — | 用原声 / 静音 / 配乐 / 解说覆盖；指向 `../02-配音与音频/` |
| `rights_scope_check` | enum | ✓ | `in_scope / needs_recheck / out_of_scope`；见 §四 |
| `conflicts_with` | list[theme_id] | — | 与哪些主题的哪一字段冲突（通常为空） |
| `outcome` | str | — | 发布后回填：采用/弃用、完播或评审反馈摘要 |
| `feedback_ref` | str | — | 指向 `../08-RSI自进化/案例库/<CASE-ID>/自进化记录.md` |

**`rationale` 示范**：

> ① 观察：MDC `content.timeline` 记 00:03–00:08 为「空镜，无人物、无字幕、无品牌物」，`style.measured` 记该段 `shot_median_s` 偏长、`integrated_lufs` 平稳｜② 依据：MDC 时间码锚点 + 抽帧拼图第 1 行（E1/E2）｜③ 推断：适合承担无需信息负载的情绪开场｜④ 动作项：剪入 5 s，慢放至 80%，前留 1 s 黑场，不叠字幕｜⑤ 置信度：高（画面事实可复核，同主题过往 2 次同类用法反馈良好）。

被丢弃的反例：「这段挺有感觉，拿来开头」——没有依据、无法复用、无法归因。

## 三、检索：命中缓存后如何「按标签找素材」

有了 MDC，找素材不再需要模型：

```bash
PY="scripts/material_cache.py"
# 列出某素材被哪些主题用过
python "$PY" themes "D:/素材/海边日落.mp4"
# 全库统计（素材数 / 主题数 / 命中率 / 估算节省）
python "$PY" stats
# 文本检索：按 affordances 与画面文字找候选（不花 token）
grep -rl "affordances" "$MDC_HOME/cards/" | xargs grep -l "环境气氛"
grep -rl "onscreen_text" "$MDC_HOME/cards/" | xargs grep -l "禁止停车"
```

选段决策顺序：**先读 MDC 的 `affordances` / `timeline` / `edit_notes` → 再看该主题已有的适配记录 → 最后才考虑新请求模型**。若三处都不足以判断，优先本地抽帧（`ffmpeg -ss … -frames:v 1`），仍不足才走 `02` 的「补充请求唯一合法路径」。

`edit_notes.continuity_risks` 是跨主题复用最容易被忽略的字段：同一段黄昏逆光素材，在 A 主题里接室内冷调镜头没问题（有意对比），在 B 主题里接另一个黄昏镜头就必须核对轴线与色温。冲突属于**成片内部**问题，不影响 MDC，也不影响其他主题的适配记录。

## 四、引用治理

| 规则 | 内容 |
| --- | --- |
| 引用计数 | `themes/<MID>.csv` 行数即被采用主题数；`stats` 汇总 Top 素材 |
| 幂等 | 同一 `(theme_id, clip_ranges)` 重复 `use` 不重复计数，只更新时间 |
| 只追加 | 适配记录不删除；弃用写 `outcome: 弃用 + 原因`，保留判断轨迹 |
| 撤销 | 授权撤回时把 MDC 标 `blocked`；**所有引用它的主题记录自动失效但不删除**，成片侧走 `../06-成片审查/02` 的替换流程 |
| 授权范围 | `rights_scope_check` 必须逐主题判断：授权常限「用途 / 地域 / 期限 / 媒介」，同一素材在 A 主题 in_scope 不意味着 B 主题也 in_scope |
| 版本关联 | 素材换版（新 MID）时，旧 MID 的适配记录不自动迁移；逐条人工确认后以新 MID 重新登记 |
| 并发 | 多主题同时写同一 `themes/<MID>.csv` 由工具加锁串行化，行级不丢 |

**冲突三种，别混**：

1. **事实冲突**（两个主题对素材内容描述不一致）→ 几乎必然是有人改了 MDC 或用了 STALE 卡，回 `verify`，以 `E1` 客观值与原片为准。
2. **用法冲突**（同一片段在两个成片里剪法不同）→ **不是冲突**，成片彼此独立，各自保留。
3. **授权冲突**（用途超范围）→ 阻断该主题，走法务/授权复核，与描述无关。

## 五、纠错回写：只改该改的那一层

| 发现的问题 | 改哪层 | 是否重跑模型 |
| --- | --- | --- |
| 「秋日怀旧的开场选段不对」 | L2 适配记录的 `clip_ranges` / `outcome` | 否 |
| 「这段其实有轻微人声，卡片写无人声」 | L1 MDC `content.spoken`，`card_version+1` + `corrections` | 否，本地听一遍/ASR 即可 |
| 「地名填错了」 | L1 MDC `where.place_name`，强制附 E2 凭证 | 否 |
| 「素材被重新导出，时长变了」 | 新 MID + 新卡；旧卡 `superseded` | 是（新素材） |
| 「模型对风格的整体判断普遍不准」 | **不是改卡片**，是改提示词/评估规则，进 `../08-RSI自进化/05` 的候选流程 | 候选阶段不涉及 |

**硬护栏**：自进化引擎**不得**自动改写 L1 客观描述（`E1`/`E2` 字段）。它只能提议修改提示词模板、字段权重或适配层规则，且须走 08 卷九步闸门与人工签字。理由很直接：把「系统觉得自己更懂」自动写回事实层，一次污染会随缓存扩散到之后所有主题。

## 六、示范：一次完整的多主题复用

```
15:02  lookup 海边日落.mp4（秋日怀旧主题）→ MISS
15:03  ffprobe + reference_probe.sh        → E1 规格与切点（0 token）
15:05  一次全量模型请求（低分辨率）       → 18,000 est_tokens
15:08  填 MDC → validate V1–V8 通过 → register
15:10  use T-2026-秋日怀旧 / 00:03-00:08 / 开场空镜     → 直接读卡，0 token
15:14  lookup（气候科普主题）             → HIT，0 token
       use / 00:12-00:19 / 论证画面
15:20  lookup（旅游推广主题）             → HIT，0 token
       use / 00:00-00:05 / 建立镜头
15:26  lookup（品牌片尾主题）             → HIT，0 token
       use / 00:20-00:24 / 收束
16:00  stats → 1 MISS + 3 HIT / 命中率 75% / 估算节省 54,000 视频输入 token
16:01  发布反馈 → 逐主题写 outcome → 汇总进 08 卷自进化记录（候选，不改规则）
```

四个主题、一次模型请求。口径：`无缓存 4×18,000=72,000` vs `有缓存 1×18,000=18,000`，净节省 `54,000 = 3 次 HIT × 18,000`，与工具 `stats` 一致；一般式 `1 − 1/N`。这些数字均为**估算**，真实账单以 `usage_metadata` 为准。若建卡作为独立步骤不绑定主题，会多一次 `HIT`，统计略偏乐观。

## 七、常见错误与排查

| 错误 | 正确做法 |
| --- | --- |
| 把「适合某主题」写进 MDC | 写 L2；MDC 保持主题中立（V8 会警告） |
| 每个主题新建一张卡 | 同 `content_hash` 只一张卡，多主题共用 |
| 授权期限只查一次 | 每个主题、每次发布都要 `rights_scope_check` |
| 素材换版后沿用旧适配记录 | 新 MID 需逐条人工确认后重新登记 |
| 弃用记录直接删掉 | 写 `outcome: 弃用 + 原因`，反例是回归集的资产 |
| 两个主题剪法不同就以为数据冲突 | 用法不同不是冲突，各自保留 |
| 让自进化引擎自动修 MDC | 禁止；只能提议改提示词/规则并走九步闸门 |

## 八、速查清单

- [ ] 每条适配有 `theme_id`、片段、`narrative_role`、五段式 `rationale`
- [ ] `rationale` 的依据引用了 MDC 字段或时间码，而非印象
- [ ] `rights_scope_check` 逐主题填写，非 `in_scope` 一律阻断
- [ ] 引用计数与 `outcome` 已回填
- [ ] 弃用与撤销只追加、不删除
- [ ] 事实冲突回 `verify` 并保留 `corrections`
- [ ] 素材换版时旧适配不自动迁移
- [ ] 关键结论的错误没有被自动写回 L1

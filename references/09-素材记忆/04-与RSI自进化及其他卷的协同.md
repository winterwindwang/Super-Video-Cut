# 与 RSI 自进化及其他卷的协同

> 分类：素材记忆 | 主题：把素材记忆接入 RSI 六层架构、跨会话持久化、护栏与全库路由 | 整理日期：2026-11-10 | 适用：把 00–09 卷组装成一个可调用的剪辑 skill 时；以及每次「参考视频 + 自有素材」同时出现的任务

> ⚠️ 本卷为创作与工程流程参考，**不构成法律意见**；合规与审查结论以 `../05-版权法规/`、`../06-成片审查/` 为准，商用项目请法务复核。

## 一、「记住」= 落盘，不是留在上下文里

用户说的「你需要记住」，在本知识库里有一个明确的技术含义：

| 记忆形态 | 能活多久 | 换主题/换会话后 | 本卷选择 |
| --- | --- | --- | --- |
| 对话上下文 | 单次会议，且受上下文窗口限制 | 丢失 | ✗ |
| 模型参数（微调/记忆功能） | 长，但不可审计、不可回滚 | 不可解释 | ✗ |
| **文件化描述卡 + 内容哈希索引** | 永久，可 diff、可回滚、可 grep | **完整保留** | ✓ |

因此「记住素材讲了什么、在哪拍、什么风格」落到 `缓存库/cards/<MID>.yaml`，身份落到 `index.csv`，每次复用落到 `usage.csv` 与 `themes/<MID>.csv`。任何新会话只要能读这个目录，就拥有全部记忆；不依赖我「恰好还记得」。

这点对 RSI 尤其重要：08 卷的自进化需要**跨任务可比的历史输入**。如果每次素材理解都靠临时上下文，回归集里的「输入」根本不可复现，九步闸门第 4 步「在冻结回归集上跑候选」就无从谈起。MDC 让输入快照变成静态文件，回归才成立。

## 二、接入 RSI 六层架构

| RSI 层（08 卷） | 原有职责 | 09 卷补上什么 |
| --- | --- | --- |
| **L0 感知层** | 客观探测 + 带时间码观察 | **持久化**：`fingerprint` + ffprobe + `reference_probe.sh` 结果写进 MDC `identity` / `style.measured`，一次测量全项目复用 |
| L1 评估层 | 参考视频 7 维评估 + 五段式说明 | MDC 的 `style.style_notes` 沿用同一套说明约束与 E1–E4 等级，口径统一 |
| L2 表征层 | `sfp-v1` 风格指纹 | `mdc-v1` 描述卡；两者通过 `source_material_ids` 互相引用，**不合并** |
| L3 执行层 | 指纹 → 剪辑方案 → 时间线 | L2 主题适配层提供「哪段素材、当什么角色、怎么剪」，是执行层的直接输入 |
| L4 审查层 | 成片与指纹偏差比对 + 06 卷审查 | `verify` 与 `rights_status` 作为审查前置；`blocked/unknown` 直接阻断 |
| L5 元层 | 误差归因、候选修订、规则演进 | 命中率、描述准确率、STALE 率、主题 `outcome` 成为新的归因信号 |

08 卷把 L5 定义为「改进 L1 评估权重与 L3 映射规则」。09 卷不新增可自我修改的层，只提供**可复现的输入与可观测的信号**——这恰好是 L5 之前一直缺的地基。

## 三、合并后的完整触发流程

当指令同时包含「参考某热门视频的风格」和「用我的这些素材」时：

```
S1 合规前置（08/01 §六 + 05 卷）：只分析参考片，不复用其表达
M1 fingerprint 每个自有素材
M2 lookup
     ├─ HIT  → 读 MDC，0 次模型请求
     └─ MISS → 本地 E1 探测 → 一次全量模型请求 → validate → register
S2 参考视频跑 reference_probe.sh（08 卷）
S3 全片通看 2 遍 + 关键段逐帧
S4 填 08 卷评估表（7 维，每项五段式）
S5 产出 sfp-v1 风格指纹 + 一页结论
     ★ 结论中必须列出「本片可用素材清单」——直接引用 MDC 的 affordances，
       不再对素材另起一次模型分析
S6 ★ 用户确认门 ★（未确认不输出成片）
S7 映射：指纹参数 × MDC 事实 × L2 主题适配 → 剪辑方案 → 时间线
        每条 use 记录写 (mid, theme, clip, role)
S8 06 卷成片审查 + verify → 发布反馈 → 08 卷自进化记录（候选，不直接生效）
```

**M2 必须早于 S4**：先知道手上有什么素材，评估参考片时才能判断「这条风格参数我的素材撑不撑得住」（08/04 的「素材降级」环节）。顺序反了会先定下一套做不到的节奏，再被迫返工。

## 四、护栏增补（对 08 卷 §五 的补充，不改其七条编号）

08 卷列了七条不可变基线。09 卷引入缓存后，**追加一条不可由自进化引擎自动修改的约束**：

> **8. L1 客观描述层只读**：`mdc-v1` 中 `E1`/`E2` 字段（身份、内容事实、时间码、地点凭证、客观测量、授权状态）不得由自进化引擎自动改写；纠错只能由人工确认后生成 `card_version+1` 并留 `corrections`。引擎可提议修改的是提示词模板、字段权重、适配层规则，且须走九步闸门与人工签字。

理由：缓存会把一次错误放大到之后所有主题。若允许引擎「自己觉得更准」就改事实层，错误会随命中率上升而扩散，且 `usage.csv` 里那些 `HIT` 看起来完全正常，极难发现。

配套的四条操作约束：
- `HIT` 后禁止对同一文件再次发起视频理解请求（补充路径见 `02` §四）。
- MDC 不得包含主题名、项目名与用途结论（V8）。
- 授权状态为非 `cleared` 时，任何自进化实验都不得把该素材纳入回归集或训练素材。
- `缓存库/audit.log` 与 `usage.csv` 只追加，纳入 08 卷「历史版本与审计日志」同等保护。

## 五、新增元指标（并入 08 卷 §八 的四组指标）

| 组 | 新指标 | 定义 | 警戒信号 |
| --- | --- | --- | --- |
| 评估质量 | **描述准确率** | 每季度抽查 ≥10 张卡的 E2 事实与时间码，与原片比对的一致率 | <95% 应暂停自动复用，检查提示词 |
| 系统健康 | **缓存命中率** | `HIT / (HIT + MISS)` | 长期偏低 → 哈希口径/目录配置有问题，或素材频繁换版 |
| 系统健康 | **STALE 率** | `STALE / lookup 总数` | 偏高 → 素材管理混乱，先治理版本再谈进化 |
| 资源 | **估算节省 token** | `Σ HIT × duration × rate` | 仅作趋势观察，**不得当作优化目标**（会诱发为刷命中率而乱复用） |
| 结果质量 | **主题 `outcome` 分布** | 采用/弃用比例与原因分类 | 某类素材反复弃用 → 该 `affordances` 标签口径需修 |

重要：命中率与节省 token 是**效率指标**，不是质量指标。把它们当成 KPI 会诱发「明明素材变了还强行命中」这类投机行为，属于典型的代理指标过优化（08 卷 §八 已警示）。

## 七、作为 skill 落地时的最小调用顺序

若把全库封装为可调用 skill，素材相关的最小执行契约：

```
1. 输入：素材路径列表 + （可选）参考视频 + 主题 ID
2. for 每个素材: fingerprint → lookup
3. 若存在 MISS: 先本地 E1 探测，再一次全量模型请求 → validate → register
4. 输出「素材清单摘要」：每条一行 = MID + summary + place + 风格关键词 + affordances + rights_status
5. 有参考视频则进入 08 卷 S1–S6；确认后才用第 4 步清单做选段
6. 每条选段写 use；交付前 verify + 06 卷审查
7. 反馈写 outcome；只产生候选，不改 MDC 事实层
```

第 4 步就是用户说的「直接读视频相关描述」：一次输出、多个主题共享、可读可 grep 可审计。

## 八、常见错误与排查

| 错误 | 正确做法 |
| --- | --- |
| 把记忆放在对话里，换会话就忘 | 文件化 MDC + 索引，任何会话先 `lookup` |
| 先评估参考片再看自有素材 | M2 早于 S4，否则风格定完才发现素材撑不住 |
| 让自进化引擎自动修 MDC 事实 | 禁止；人工纠错生成 `v+1` 并留痕 |
| 把命中率当质量 KPI | 它是效率指标；质量看描述准确率与 `outcome` |
| 用 MDC 代替授权审查 | 卡片只是台账指针，表 C 仍须人工签字 |
| MDC 与风格指纹合并成一个文件 | 两者 ID 互引但职责不同，合并会让「参考片评估」与「素材描述」互相污染 |
| 回归集用了 `rights_status: unknown` 的素材 | 一律排除，先补授权 |

# 09 · 素材记忆与描述缓存卷

> 分类：素材记忆 | 主题：一次视频模型调用产出可复用素材描述，跨主题直接读缓存 | 整理日期：2026-11-10 | 适用：任何「要分析/理解/采用某段视频素材」的任务，尤其是同一素材被多个主题反复采纳

> ⚠️ 本卷为创作与工程流程参考，**不构成法律意见**；卡片中的授权、肖像、地点与来源信息须经人工复核，商用项目请法务复核，详见 `../05-版权法规/`。

**一句话**：一段素材只让视频模型「看」一次。看完把**讲了什么、在哪里拍、什么风格、能不能用**写成结构化素材描述卡（MDC）落盘；之后无论换多少个主题、隔多少天、换多少次会话，都先查缓存、命中就直接读卡片，**不再重复请求视频模型**。

---

## P0 协议（贴在墙上）

```
收到「用这些素材剪一个 XX 主题」或「分析一下这段素材」
  → M1 算内容指纹（material_cache.py fingerprint）
  → M2 查缓存（material_cache.py lookup）
       ├─ HIT  → ★ 禁止再调用视频模型 ★
       │         直接读 cards/<MID>.yaml；只做「主题适配」这一层轻判断
       │         写一条 use 记录（主题 / 采用片段 / 用途）
       └─ MISS → 先跑本地客观探测（ffprobe + reference_probe.sh / qc_scan.sh）
               → 用 模板/模型分析提示词.md 做【一次】全量描述请求
               → 填 模板/素材描述卡模板.yaml → register 写缓存
               → 再进入主题适配
  → M3 若素材字节变化 / 描述被证伪 / 授权到期 → 失效并重做或标 blocked
```

**四条不可让步**：
1. **命中即只读**：HIT 时不得对同一文件再次发起视频理解请求；确需补充，优先用本地手段（抽帧、ASR、ffprobe），且写回卡片并记 `reason`。
2. **一次写全**：MISS 时的那一次模型请求必须一次问全「内容 / 地点 / 风格 / 可用性 / 时间码事件」，不允许为不同主题分次重问。
3. **客观与适配分离**：素材本身的描述（MDC）永久且主题无关；某主题怎么用（主题适配层）单独存，绝不回写污染 MDC。
4. **描述不等于授权**：卡片里的 `rights` 只是台账指针，能不能用仍走 `../05-版权法规/` 与 `../06-成片审查/02`。

## 三层结构：为什么要分层

| 层 | 存什么 | 会不会随主题变 | 生命周期 |
| --- | --- | --- | --- |
| **L0 文件身份层** | 内容哈希、字节数、ffprobe 规格、别名与路径 | 不会 | 素材字节不变则永久有效 |
| **L1 素材描述层（MDC）** | 讲了什么、在哪拍、什么风格、画面/声音事实、可用性 | **不会** | 一份素材一张卡；纠错只增版本不覆盖 |
| **L2 主题适配层** | 这个主题下取哪几秒、当什么叙事角色、为什么合适、效果反馈 | **会** | 一素材 × 一主题一条，可无限追加 |

> 用户的原话是「一个素材可以被很多不同的主题同时采纳」——正是 L1 与 L2 必须分层的原因。若把「适合做怀念向开场」写进 L1，换做「科技测评」主题时这条描述就变成了噪声甚至误导。

**与 08 卷的边界**（最容易混）：

| | 参考视频评估（08 卷） | 素材描述卡（本卷） |
| --- | --- | --- |
| 对象 | 别人的热门视频，用来**提取风格参数** | 自己要入时间线的素材，用来**理解内容** |
| 目的 | 「这条片子为什么好看」→ 风格指纹 `sfp-v1` | 「这段素材里有什么」→ 描述卡 `mdc-v1` |
| 深度 | 7 维 30+ 项，每项五段式说明，S6 用户确认门 | 4 组事实字段 + 风格推断说明，人工抽查即可 |
| 复用 | 通常一次性，评估结论进入规则库 | **高频复用，命中即读** |
| 同一文件身兼两职 | 允许，但必须分别产出评估表与 MDC，两个 ID 互相引用 | 同左 |

## 一次调用能省多少（估算口径）

Google 官方文档给出的静态视频处理口径：默认 1 FPS 采样，低 `media_resolution` 每帧 66 token、音频每秒 32 token，合计约 **100 token/秒视频**；高分辨率每帧 258 token，合计约 **300 token/秒**；另有官方 Firebase 文档给出 **263 token/秒** 的另一口径（版本与统计范围不同，标「待核实」）。

据此，**一段 3 分钟素材在低分辨率下约 18,000 输入 token**。若被 4 个主题采纳（首次建卡的 `MISS` 顺带服务第一个主题，之后 3 次 `HIT`）：

| 方案 | 视频模型请求次数 | 估算视频输入 token |
| --- | --- | --- |
| 无缓存，每主题重看一遍 | 4 | 72,000 |
| 厂商 Files API / 上下文缓存 | 4（每次仍计费，仅降带宽/单价） | 4 次按缓存单价计，且有 TTL 过期 |
| **本卷 MDC 缓存** | **1** | **18,000** |

`stats` 的口径：`命中率 = HIT/(HIT+MISS) = 3/4 = 75%`，`估算节省 = Σ(HIT × est_tokens) = 3 × 18,000 = 54,000`，与无缓存基线 `72,000 − 18,000 = 54,000` 一致；一般式 `1 − 1/N`（N 为主题数）。若把建卡当作独立步骤、不绑定任何主题，会多一次 `HIT`，统计略偏乐观，属正常。

节省不是精确的账单数字：上表只算视频输入 token，未含提示词、输出与推理 token；真实节省以服务返回的 `usage_metadata` 为准，工具支持把实测值写入 `usage.csv`。**厂商侧缓存与本卷缓存是叠加关系**，不是二选一。

## 命令速查

```bash
PY="scripts/material_cache.py"

# 1. 先问缓存（任何素材分析前第一步）
python "$PY" lookup "D:/素材/海边日落.mp4"

# 2. 未命中：本地客观探测（不花模型 token）
bash "scripts/reference_probe.sh" "D:/素材/海边日落.mp4" /tmp/probe
ffprobe -v error -show_format -show_streams -of json "D:/素材/海边日落.mp4"

# 3. 用模板提示词做一次全量描述 → 填 MDC → 登记
python "$PY" register "D:/素材/海边日落.mp4" --card "/tmp/MID-xxx.yaml" --model "<模型名>" --tokens 18000

# 4. 之后任意主题复用：只记一条适配，不碰模型
python "$PY" use "D:/素材/海边日落.mp4" --theme "T-2026-秋日怀旧" --clip "00:00:03-00:00:08" --note "开场空镜"
python "$PY" use "D:/素材/海边日落.mp4" --theme "T-2026-气候科普" --clip "00:00:12-00:00:19" --note "云层示意"

# 5. 体检与统计
python "$PY" verify "D:/素材/海边日落.mp4"
python "$PY" themes "D:/素材/海边日落.mp4"
python "$PY" stats
```

`lookup` 打印 `HIT` 时，输出里会明确带一行「**禁止再次调用视频模型**」——这是给执行者的硬提醒，不是建议。

## 速查清单

- [ ] 分析任何素材前先跑 `lookup`，HIT 就直接读卡片
- [ ] MISS 时先本地探测，再把「一次写全」提示词发给模型
- [ ] 卡片四组字段齐全：内容 / 拍摄地点 / 风格 / 可用性，每条带证据等级
- [ ] 地点与身份类信息不得无依据猜测，标 `E3 推断` 或 `E4 假设`
- [ ] 风格类推断沿用五段式说明（观察 / 依据 / 推断 / 动作项 / 置信度）
- [ ] `register` 通过 `validate` 后才入库；纠错生成 `v+1`，不覆盖旧版
- [ ] 每次复用写 `use`，主题适配绝不回写 MDC
- [ ] 授权到期标 `blocked` 而非删卡；`06-成片审查/02` 表 C 仍要人签
- [ ] `stats` 里的节省是估算，账单核对以 `usage_metadata` 为准

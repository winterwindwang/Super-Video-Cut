# 一次全量素材分析 · 模型提示词模板

> 分类：素材记忆 | 主题：MISS 时那「一次」视频理解请求的完整提示词 | 整理日期：2026-11-10 | 适用：任何视频理解模型/多模态服务；配合 `素材描述卡模板.yaml` 使用

> ⚠️ 本卷为创作与工程流程参考，**不构成法律意见**；模型输出一律视为待核对素材，授权、地点与身份结论须人工复核。

---

## 使用规则（先读这五条）

1. **只在 `lookup` 返回 `MISS` 或 `STALE` 时使用**。`HIT` 时禁止发送本提示词。
2. **一次只发一次**。把下方 `<本地E1数据>` 与 `<素材别名>` 替换后整段发送，一次问全五个维度；不要为不同主题拆成多次提问。
3. 先把本地客观数据（ffprobe 规格、`reference_probe.sh` 的切点/响度/色彩统计、抽帧拼图）作为上下文附上，让模型不必重复「猜」规格，也减少幻觉。
4. 模型输出**不是成品卡**：人工逐条核对、标证据等级、补五段式说明、填授权信息后，才 `validate` → `register`。
5. 长素材：静态模式默认 1 FPS，快速运动可能漏细节；可按官方支持的方式降低 FPS 或分段，但须交叉抽帧验证。时间戳一律 `MM:SS` 或 `MM:SS.mmm`。

---

## 提示词正文（可直接复制）

```
你是视频素材编目员。请【一次性】完整分析下面这段视频，输出可直接填入素材描述卡的 YAML。
这份描述会被之后的许多不同主题反复复用，因此必须主题中立、事实与推断分离、可复核。

【已知客观数据（由本地工具测得，视为 E1，不要再推测）】
<本地E1数据>
# 例：duration=180.0s, 1920x1080, 25fps, h264/aac 48kHz
# 切点: 0.00 / 12.40 / 31.08 / 58.20 ; 镜头时长中位数=18.4s
# integrated=-16.2 LUFS, TruePeak=-1.4 dBTP, YAVG=104, SATAVG=31
# 附：抽帧拼图（每行标注时间码）

【素材别名】<素材别名>

【输出要求】
1. 只输出一个 YAML 代码块，字段名严格使用 content / where / style / usability 四组，
   与 mdc-v1 一致：content.{summary, subjects, actions, timeline[{tc,event,evidence}],
   spoken{has_speech,language,key_lines,transcript_ref}, onscreen_text, affordances,
   notable_absences}；where.{setting_type, place_name, place_basis, landmarks,
   environment{time_of_day,weather,season,light_direction,light_quality,background,props},
   camera{position,angle,height,movement,stability}, geo_hint, inference_note}；
   style.{genre, visual{...}, measured{}, audio{...}, mood, rhythm,
   style_notes[{观察,依据,推断,动作项,置信度}], similarity_caveat}；
   usability.{quality_issues, edit_notes{best_ranges,avoid_ranges,continuity_risks}}。
   不要输出 identity / meta / constraints（这些由本地填写）。
2. 每条事实挂 evidence：E1=沿用上方客观数据；E2=画面/声音中可指认且带时间码；
   E3=基于 E1/E2 的推断（必须写「依据」与「可证伪条件」）；E4=无法核实（尽量不用）。
3. content.timeline 至少 3 个时间码锚点；超过 60 秒的素材每 15–30 秒一个锚点，
   按时间递增，覆盖开头、中段、结尾。每个 onscreen_text 与 quality_issues 都带时间码。
4. summary ≤80 字，主谓宾齐全，不写「很美/高级/有质感」这类评价词。
5. 【地点与身份硬约束】where.place_name 只有在画面内可指认文字/地标，或已知拍摄记录时
   才可以填；否则必须为 null，place_basis 写「无」。禁止仅凭海、山、植被、建筑风格
   推断城市或国家。这类印象只能写进 where.inference_note，标 E3 并说明可证伪条件。
   不得猜测人物身份、职业、年龄、关系；只描述可指认的外观与行为。
6. 【主题中立硬约束】输出中不得出现任何具体主题名、项目名、客户名、
   「适合做XX主题/适合开场/适合片尾」这类用途结论。content.affordances 只允许填
   中立标签：空镜 / 人物表情 / 产品特写 / 动作过程 / 环境气氛 / 数据画面 / 同期声。
7. style.style_notes 至少 2 条，每条必须含齐五段：
   观察（带时间码或数值）、依据（证据等级 + 具体来源）、推断（明确写「这是推断」）、
   动作项（对剪辑有什么用）、置信度（高/中/低 + 理由）。
   mood 最多 3 个词，每个词后附一句画面或声音依据。
8. 【表达与隐私】key_lines 只写要点与时间码，不整段抄录台词；不要转录歌词全文；
   不写入真实姓名、证件号、车牌、门牌等个人信息；如画面出现这些，只在
   usability.quality_issues 里写「00:00 画面内疑似含车牌，需人工脱敏」。
9. 不确定的一律写 unknown / null，不要编造。严禁输出「根据常见情况推测」这类填充语。
10. 结尾附一段 CHECK：列出你认为最需要人工复核的 3 个字段及原因。
```

## 发送前的自检

- [ ] `lookup` 确认为 `MISS` / `STALE`
- [ ] `<本地E1数据>` 已填入 ffprobe + `reference_probe.sh` 结果，抽帧拼图已附
- [ ] 目标服务已设置合适的 `media_resolution` / FPS / 处理模式（长视频按官方建议）
- [ ] 提示词中的「主题中立 / 禁止猜地名 / 五段式说明」三条硬约束未被删改
- [ ] 已声明输出为 YAML 且字段与 `mdc-v1` 对齐

---

## 收到输出后的处理

| 步骤 | 动作 |
| --- | --- |
| 1 | 抽查 ≥3 个时间码锚点与原片比对（模型常见「总结合理但具体时刻不准」） |
| 2 | 把所有 `E3` 推断补上依据、置信度、可证伪条件；无依据的删掉 |
| 3 | 检查 `place_name` 是否有 E2 凭证，无则改为 `null` |
| 4 | `style.measured` 以本地 E1 数据覆盖模型数值（模型不该推测这些） |
| 5 | `usability` 的授权、肖像、隐私项**全部由人工从凭证填写**，不采信模型 |
| 6 | 复制到 `素材描述卡模板.yaml`，填 `identity` / `meta` / `constraints` |
| 7 | `python scripts/material_cache.py validate <卡片>` → 通过才 `register` |
| 8 | 把本次实际 `usage_metadata` 的 token 数写入 `register --tokens`，供 `stats` 核对 |

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 为「秋日主题」「科普主题」各发一次 | 只发一次；主题判断放 L2 适配层 |
| 提示词里让模型「顺便判断适合什么主题」 | 删掉，会污染卡片并诱发后续重复请求 |
| 直接把模型输出当成品卡登记 | 必须人工核对 + `validate` |
| 让模型补充 ffprobe 能测的规格 | 本地 E1 数据先给，省 token 也更准 |
| 输出里出现「像在三亚」 | `place_name: null`，印象写 `inference_note` 标 E3 |
